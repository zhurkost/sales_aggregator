# Правила для агентов в этом репозитории

Этот файл читает любой агент (Codex, Claude Code и другие) перед работой.
Он короткий намеренно: правила здесь обязательны, подробности — в файлах, на которые он ссылается.

## Проект

Автопост: одна карточка товара или квартиры → подготовка значений → расширение браузера
заполняет формы площадок Беларуси (Kufar, Onliner, Realt, Domovita и др.).

| Часть | Где | Стек |
| --- | --- | --- |
| Сервер | `backend/` | Spring Boot 3.5, Java 17, SQLite (JDBC) |
| Кабинет | `frontend/` | Angular 21, vitest |
| Общие модели старого модуля объявлений | `lib/` | TypeScript |
| Расширение | `extension/` | Chrome MV3, чистый JS |
| Справочники аренды | `data/rental/apartments_long_term_rent/` | JSON, едут в релиз вместе с кодом |
| Исследования форм | `docs/parsing/`, `data/parsing/` (будут перенесены в `research/`) | текст, JSON |

## Команды

```sh
npm ci && npm --prefix frontend ci     # зависимости
npm test                                # тесты lib/ и расширения (node --test)
npm run test:frontend                   # тесты Angular (vitest)
npm run test:backend                    # тесты Spring (Maven; нужен доступ к Maven Central)
npm run build                           # сборка Angular + Spring
java -jar backend/target/autopost-api.jar --validate-rental-reference=data/rental/apartments_long_term_rent
```

Если в песочнице недоступен Maven Central, Java-изменения проверить нельзя. Тогда
**не меняй Java-код**: запиши задачу в отчёт фазы как заблокированную и переходи к следующей.

## Обязательные правила

1. **Прочитай задание целиком до первого изменения.** Рефакторинг аренды:
   `docs/refactoring/rental/README.md`, затем файл своей фазы. Ревью, из которого выросли
   задачи: `docs/refactoring/rental/review.md`.
2. **Ветка.** Вся работа — в ветке `claude` (или в рабочей ветке от её вершины, которую потом
   вливают в `claude` fast-forward). В `master` не коммитить и не пушить.
3. **Маленькие коммиты.** Один логический шаг — один коммит, формат Conventional Commits:
   `fix(rental): …`, `refactor(rental): …`, `test(extension): …`. Каждый коммит собирается
   и проходит тесты.
4. **Типы вместо сырого JSON.** `JsonNode`, `ObjectNode`, `Map<String, Object>` и TypeScript `any`
   допустимы только на границе разбора входа. Дальше — Java records / sealed interface и
   типизированные TS-интерфейсы. Новый код на сыром JSON не принимается.
5. **Одна правда.** Если правило нужно и серверу, и браузеру, его вычисляет сервер, а клиент
   показывает результат. Не дублируй логику в Java и TypeScript.
6. **Без преждевременной совместимости.** Не добавляй адаптеры старых форматов, режимы
   «на всякий случай» и шимы «для прежнего контракта». Модуль аренды не имеет внешних
   пользователей API. Если есть сохранённые данные старого формата — одноразовый скрипт
   миграции, а не вечная ветка в коде.
7. **Ничего не выдумывать про площадки.** Селекторы, коды вариантов, URL форм и правила
   берутся только из отчётов исследований (`data/parsing/**/report_*.txt`), рабочих
   справочников или сохранённых снимков форм. Нет доказательства — пометь поле
   `needs_research` с конкретным вопросом и не автоматизируй его.
8. **«Готово» = проверено.** Для каждого исправления — тест, который падал до него.
   Все три набора тестов зелёные. Изменение справочников проходит валидатор.
   «JSON прошёл валидатор» не означает, что форма заполняется.
9. **Никаких неиспользуемых настроек.** Ключ в JSON, который код не читает, удаляется.
   Схемы справочников запрещают неизвестные ключи.
10. **Безопасность.** Не коммить и не печатай токены, ключи, `.dev.vars`, содержимое
    `/mnt/user-data/uploads`. Не открывай рабочий VPS, не деплой, не выполняй реальную подачу
    объявлений на площадках.
11. **Документация короткая.** Не создавай новых длинных документов. Архитектура —
    в `docs/rental-architecture.md` (не больше двух страниц после рефакторинга), решения —
    короткие ADR в `docs/adr/`, история — в `CHANGELOG.md`. Задания агентам — только в
    `docs/refactoring/` и `docs/agents/`.
12. **Заблокирован — не обходи.** Нет сети, доступа, данных или решения владельца: остановись
    на этом пункте, опиши блокер в отчёте, продолжай с независимыми пунктами.

## Отчёт в конце работы

В конце фазы допиши в `docs/refactoring/rental/progress.md` раздел:

```
## Фаза N — <дата>
Сделано: <пункты с хэшами коммитов>
Тесты: npm test <pass/fail>, test:frontend <…>, test:backend <… или «не запускался: причина»>
Не сделано и почему: <пункты>
Вопросы владельцу: <если есть>
```
