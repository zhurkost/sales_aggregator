2. Источники и способ сбора
https://api.kufar.by/insertion/v1/meta/bootstrap?application=ad_insertion&category=2010&company_ad=0&parent=2000&platform=web&routing=web_ad_insertion&taxonomy-version=2
https://api.kufar.by/catalog/v1/nodes?tag=category_2010&view=taxonomy
Каталог моделей: tag=<value марки>; поколений: tag=<value модели>.
Шаблоны и реальные запросы наблюдались в Network формы. Значения тегов
берутся только из предыдущего ответа. Прямой массив, без pagination envelope.
Списки остальных полей — из ad_metadata.parameters.refs и правил dispatcher.
Bootstrap содержит также другие категории: они не объединяются с легковыми авто.
Аномалия источника: Kia Rio X / I (generation_riox_i_2020) имеет node_type=model,
но name=cars_gen_v2, url_name=cgen2 и код поколения под запрошенной моделью.
Уровень определён по этим согласованным признакам; исходный node_type сохранён.
Исключение строго для этого кода; неизвестные несоответствия по-прежнему останавливают сбор.
Каталог не фильтруется по content-count, популярности, году или дате.
Состояние «с пробегом» не является параметром taxonomy endpoint: ограничение
зафиксировано в самой форме и в option condition, а не выводится из наличия объявлений.
Метаданные получены: 2026-11-12T09:34:09.947Z
Checkpoint каталога: 2026-11-12T11:43:15.534Z
Публичные GET без авторизации/токенов; последовательные запросы >=1100 мс.
Кэш URL+SHA256, атомарные checkpoints, продолжение после остановки, Retry-After.

4. Структура и пример
Объявлены отдельные enum-поля cars_brand_v2, cars_model_v2, cars_gen_v2.
У зависимых уровней options=[], parent_option_id ссылается на родительское поле.
Сами choice лежат один раз: brand.options -> childOptions моделей -> childOptions поколений.
Каждый узел содержит обычный стабильный id, value, level и options_complete.
Нет finalId, дерева по годам, дублирующей плоской коллекции поколений или неявного fallback.
Kia.value: category_2010.mark_kia
Rio.value: category_2010.mark_kia.model_rio
IV Рестайлинг.value: category_2010.mark_kia.model_rio.generation_rio_iv_restajling22500704
В UI Rio подтверждены восемь поколений: IV Рестайлинг, IV, III Рестайлинг,
III, II Рестайлинг, II, I Рестайлинг, I. Выбран IV Рестайлинг.
startYears/endYears сохранены в исходном evidence; не участвуют в структуре и сопоставлении.
По уточнению пользователя childOptions применяется к двум цепочкам:
марка -> модель -> поколение и регион -> город/район.
Город хранится под своим регионом; одинаковые подписи разных регионов не объединяются.
Для будущего маппинга городов используется контекст сопоставленного родителя-региона
и прямые связи ID узлов, без выбора первого совпадения по подписи.
Остальные списки также плоские. Для будущего B сопоставлять по смыслу и именам
внутри уже сопоставленных родителей, результат хранить прямыми связями ID на каждом уровне.

5. Важные факты о значениях
1.6 л -> cars_capacity="8"; 5 посадочных мест -> cars_seats="2".
Число в подписи не равно нативному коду; перевод по порядковому номеру запрещён.
Валюта: UI «руб.» -> BYR, «$» -> USD, «€» -> EUR. Метаданные BYR подписаны «р.».
Схема использует фактическую UI-подпись «руб.» и сохраняет исходный код BYR.
Год отдельный: 47 наблюдённых вариантов, включая «1980 или ранее».
condition="1" — С пробегом; наблюдённый «Новый» ("2") исключён по заданию.

6. Зависимости и ограничения
После выбора марки появляется модель, после модели — поколение.
cars_gearbox="1" (Автоматическая) -> cars_autogearbox: Автомат / Робот / Вариатор.
cars_engine="5" (Электричество) -> cars_battery_capacity; объём становится необязательным.
При возвращении к бензину ёмкость батареи исчезает, объём снова со звёздочкой.
Это тест зависимости формы на образце, не утверждение о комплектации реальной Kia Rio.
Условная обязательность объёма не выражается единственным required в контракте 2.2:
required=null; оба исходных ref 1579/7490 сохранены, зависимость не потеряна.
Сам выбор объёма проверен; условную обязательность нужно учесть при будущей runtime-интеграции.
condition="1" -> repair_needed. Регион -> обязательный список города/района.
Название maxlength=50, описание maxlength=4000, VIN maxlength=17; серверные
минимумы/регулярные выражения не выдуманы из имён валидаторов metadata.
Пробег input min=0, step=0.1, но metadata v_integer: схема integer; дробный ввод не тестировался.
Ёмкость батареи metadata v_float: схема number; UI min=0, step=0.1. Ввод 60 проверен.
Цена в UI — десятичная сумма, min=0, max=99000000, step=0.01. Transport int
не используется для вывода о единицах денежного API; сетевое сохранение не выполнялось.
Переключение Цена -> Договорная цена -> Цена очищает сумму; binding задаёт зависимость
price и currency от price_mode. Режим заполняется до суммы, не после неё.

7. Binding и проверка интерфейса
Проверены открытие/выбор списков, три уровня Kia/Rio/IV Рестайлинг, обычные поля,
чипы, условные поля, checkbox, множественные фары/характеристики, регион и валюта.
Нестандартные списки: [data-name=FIELD] [data-testid=base-dropdown-ui];
варианты внутри [data-testid=popup-body] [class*=_item_with-check], точный уникальный текст.
Чип выбран по классу _filled-green; текст всей группы не доказывает выбор.
Checkbox: hidden input.checked=true, aria-checked="1". Playwright check(role)
выдал ошибку после успешного изменения; клик label с чтением input.checked работает.
Для идемпотентности нужен handler, который сначала читает checked, затем при необходимости кликает.
Дополнительно проверен input.click(): false -> true -> повтор true; состояние сохраняется
после обновления React. Binding set_checked с target на native input помечен ready;
visible для hidden input не требуется, контроль доступности относится к видимой ветви формы.
В общий контракт добавлен необязательный verify.target для чтения выбранного chip/radio.
Фары/характеристики — multi_enum: checkbox в popup, затем «Применить».
Обычный choose single-value и проверка текста группы не заменяют проверку всего множества.
Точные DOM-наблюдения сохранены в evidence/kufar-ui-observations.json.
Закрыты все семь needs_review: VIN, фото, фары, характеристики, способ связи, обмен, торг.
Ready — проверенный рецепт, не активация runtime 2.2.
В авторизованной форме имя/телефон disabled и берутся из профиля; email не показан.
Эти три binding помечены unsupported для проверенного состояния аккаунта;
не менять профиль, не снимать disabled и не требовать повторного ввода контактов.
required=true у контактов сохранён из metadata и не означает требование редактируемого UI.
«Возможен обмен» и «Торг» проверены с изменением и readback. Способ связи — radio:
«Звонки и сообщения» (metadata 0) / «Только сообщения» (metadata 1).
Evidence ревью: evidence/kufar-authenticated-review.json; личные значения не сохранялись.
Завершённая интерактивная проверка: evidence/kufar-authenticated-interactions.json.
Multi_enum: 10 сценариев — набор, полная замена, повтор, очистка, повторный набор.
После «Применить» дождаться закрытия, открыть снова, сравнить всё множество checked.
Фиксированные 100 мс оказались недостаточны: нужен lifecycle wait и таймаут.
Новый рецепт choose/replace_set + selected_text_set_equals описан в общем контракте.
Обмен отличается от ранее проверенных boolean: быстрые input.click()/label.click()
давали нестабильный readback. Итоговый target — видимый role=checkbox, проверка —
native input.checked отдельным чтением после обработки React. Повтор true не кликает.
Выключенный aria-checked может быть пустой строкой: он не используется как boolean.
VIN: два синтетических 17-символьных значения, замена и очистка. aria-invalid=false.
Проверен перенос текста; валидность реального VIN, декодирование и отчёт не заявляются.

8. Установленные ограничения и границы проверки
kufar.name: В проверенной авторизованной форме поле disabled и берётся из профиля. Не заполнять и не менять настройки аккаунта. Другие состояния аккаунта не исследованы.
kufar.phone: В проверенной авторизованной форме поле disabled и берётся из профиля. Не заполнять и не менять настройки аккаунта. Другие состояния аккаунта не исследованы.
kufar.email: Поле есть в метаданных, но не представлено в проверенной авторизованной форме. Не синтезировать input и не переходить в настройки аккаунта.
Метаданные, не подтверждённые видимой частной формой: cars_engine_power, vin_report, content_video, cars_availability, cars_delivery_country, leasing_pro, confiscated.
Фото: max_items=30; JPEG/JPG/PNG до 10 МБ. Точное число байт неизвестно.
Проверены PNG 640x480 и JPEG 900x700. POST ads-image-uploader.kufar.by/v1/images:
HTTP 200; счётчик 2 из 30; оба серверных rms.kufar.by изображения complete/naturalWidth>0.
После первого файла #imageLoaderDropzone заменяется на #imageLoaderDropzoneSmall.
Один промежуточный JPEG 640x480/6252 байта не увеличил счётчик; причина не установлена.
Не выводить из этого минимальный размер или правило дедупликации. Рецепт files_accepted
не пропустит такой файл как успешно принятый: ожидаемое количество не совпадёт.
Серверный префикс, загрузка картинки и счётчик обязательны; одного preview недостаточно.
В непубликованной форме оставлены два синтетических тестовых изображения.
VIN очищен; контакты и профиль не менялись, объявление не публиковалось.
В форме уже видна сумма оплаты продвижения; пакеты не переключались.

9. Приёмка и воспроизводимость
Команды приведены в scripts/research/kufar-cars/README.txt.
Итоговый validate запускать без --allow-partial: он отклоняет неполные enum/childOptions.
Проверяются уникальность ID, родительские уровни, ссылки when, отсутствие циклов,
ровно один binding на поле, scope used-only и наличие образца Kia/Rio/IV Рестайлинг.
Отдельные offline-тесты проверяют чужого родителя, дубликат кода, неполный обход,
возобновление без HTTP, испорченный cache, конфигурацию ограничения частоты запросов.
Каталог и схема сопоставляются по counts и исходным нативным значениям;
hashes schema/binding/catalog находятся в evidence/kufar-crawl-summary.json.
Этап B (common/mapping других площадок), runtime 2.2 и пользовательская вкладка авто
не входят в результат этого задания. Недвижимость не изменялась.
