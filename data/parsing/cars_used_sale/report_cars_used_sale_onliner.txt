ОПТИМАЛЬНЫЙ СПОСОБ СБОРА
В пользовательском авторизованном Chrome найдены публичные запросы самой формы:
  https://ab.onliner.by/sdapi/ab.api/dictionaries
  https://ab.onliner.by/sdapi/ab.api/manufacturers/32
  https://ab.onliner.by/sdapi/ab.api/manufacturers/32/models/884
Первый запрос даёт марки/плоские справочники; второй — модели марки;
третий — ВСЕ поколения модели. Адреса подтверждены ResourceTiming и клиентом
https://ab.onliner.by/assets/app.29b40b409061398a2fa5.js.
Все 3007 запросов полного каталога выполнены без cookies/токенов. Selenium
для перебора тысяч пунктов не нужен. Браузер используется для проверки самой
формы, условий, нативных контролов и фактического сохранения значений.
Приложение-сборщик: scripts/research/onliner-cars/collect.mjs. Есть кэш,
контрольные суммы, продолжение, ограничение частоты, backoff и остановка при ошибках.

ГОДА И ДЕРЕВО
Годы не собираются в дерево и не влияют на перечисление поколений.
API-поля year/images удалены при сохранении каталога. Общий year — integer;
нет массивов годов отдельно для марки, модели или поколения.
Сама форма Onliner фильтрует список поколений по году автомобиля локально.
Это поведение сайта не переносится в сборщик: полный каталог модели сохранён.
При будущей интеграции сначала вводится год, затем нужное поколение. Если сайт
не показывает выбранное поколение для данного года, требуется ручное уточнение;
автоматически подменять поколение нельзя.

Пример нативных значений:
  manufacturer 32: Kia
    model 884: Rio
      generation 6682: (FB) Рестайлинг
У Rio сохранены все 10 поколений, включая FB, QB, JB, DC и X/X-Line.
Сайт не называет 6682 «IV Рестайлинг». Название не исправлялось под Kufar;
межплощадочное сопоставление — отдельное задание этапа B.
ID узлов включают площадку, уровень и родительский путь. value сохраняет
нативный числовой ID. childOptions содержат только дочерние choice.
У отдельных полей model/generation options пуст, варианты хранятся в дереве.

ПОЛЯ И ЗАВИСИМОСТИ
Марка → модель → поколение; страна → область → город.
Цвет, комплектация и прочие признаки — обычные плоские поля.
21 группа оборудования: часть radio/enum, часть checkbox/multi_enum.
44 отдельных checkbox оборудования. Сверены все подписи и нативные справочники.
Бензин: газовое оборудование, гибрид и объём. Дизель: гибрид и объём.
Электро: нет объёма, газа, гибрида. Мощность и момент остаются отдельными полями.
Объём — свободный ввод: dictionary engine_capacity не превращён в enum формы.
Гибрид у бензина второй checkbox, у дизеля первый: привязка использует последний
элемент соответствующего списка; обязательно условие engineType != electric.
Состояние: owned / emergency; new наблюдался, но исключён по границам задания.
Переключение состояния может очищать пробег: state заполняется до odometer.
«Не растаможен» имеет обратный смысл по отношению к API customsClearance.
Коды единиц из клиента: horse/kw и km/miles. Валюты UI: BYN, USD, EUR, RUB.
Цвет в DOM использует input[name=bodyType], как кузов на другом шаге;
исполнитель обязан работать на соответствующем шаге, а не по всей истории формы.
required=null означает неизвестную обязательность, а не необязательное поле.
Наличие input.required=false не принято за доказательство необязательности.

РЕВЬЮ ГОДА ЗАВЕРШЕНО
Проверены 7 сценариев: кнопка 2022, повтор, select 2005, повтор, граница списка
2016, граница кнопок 2017 и возврат к 2022. Каждый раз найден ровно один активный
контрол и считано ожидаемое значение после обновления UI. Исходное пустое поле
и исходное отсутствие выбранного поколения восстановлены.
Эти значения — тестовые примеры, а не сохранённый справочник годов.
Рецепт choose ищет ровно одно точное совпадение среди кнопок и option текущего
поля. Для option устанавливает значение владеющего native select и вызывает
input/change; для кнопки — click. Нет вычисления границы по календарю исполнителя.
Readback: активная кнопка либо option:checked только внутри активного контейнера
select. Неактивный select не должен добавлять второе или устаревшее значение.
Сначала model → year, затем generation: площадка может автоматически выбрать
или сбросить поколение после смены года, поэтому его надо проверять отдельно.
Свидетельства: evidence/onliner-year-review.json; проверяющая модель выбора —
scripts/research/onliner-cars/year-review.mjs. Список годов не скачивался,
дерево марка → модель → поколение не изменялось. year остаётся integer/options: [].
Все needs_review закрыты в рамках исследованной формы.
ready означает исследованный рецепт селекторов/действия/readback в указанной
форме, а не готовую поддержку этого контракта production-расширением или тест
каждого значения каждой марки. Структурные селекторы ограничены активным шагом;
при обновлении вёрстки требуется повторная проверка однозначности.

ПРИЁМКА И ГРАНИЦЫ
Проверены все source counts, ID, имена, связи родителей, отсутствие дубликатов,
полнота дочерних массивов, отсутствие годов в поколениях, соответствие binding
всем конечным полям, зависимости и отсутствие циклов. 20 offline-тестов пройдены,
включая отклонение локального preview, неправильного хоста/пути, незагруженного
изображения, неправильного счётчика и ошибочного учёта карточек-заглушек;
также проверяется защита от неоднозначного селектора телефона и ошибочного
исключения этого поля в режиме чатов; для года — выбор между кнопкой и select,
неоднозначность, недоступный вариант и устаревшее значение неактивного select.
Ни common, ни межплощадочный mapping, ни функциональность frontend/backend/
расширения не менялись. Автомобильная категория в production не подключена.
Объявление не опубликовано, платные пакеты не выбраны.
Исходные DOM-снимки и доказательства находятся в evidence/onliner-*.
