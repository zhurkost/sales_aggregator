5. СПРАВОЧНИКИ И ЗАВИСИМОСТИ
Конечные списки из раздела 4 полностью прочитаны в UI; коды не подтверждены
ни у одного enum/multi_enum. Это основной пробел для исполняемого заполнения.
DOM ID удобств (строки): 606 телефонная сеть; 611 душевая кабина; 602 посуда;
614 джакузи; 640 видеодомофон; 607 интернет.
DOM ID техники (строки): 503 холодильник; 505 посудомоечная машина; 504 СВЧ-печь;
507 телевизор; 514 кондиционер; 506 стиральная машина; 511 домашний кинотеатр;
502 мелкая бытовая техника; 512 компьютер.
Тип этих DOM id — строковый HTML-атрибут. Совпадение с нативным числовым кодом
не доказано; не переносить в choice.value автоматически.
Адрес: settlement search → выбор подсказки → включение street, house, building.
Полный перебор улиц/домов Беларуси не выполнялся и не входит в задание.
Наблюдались поиски Минск/Брест/Фаниполь, у улиц Фаниполя — первые 6 подсказок
без выбора. Данные конкретных домов не запрашивались. Формат объекта выбора,
ID, пагинация и зависимые районы не установлены. Схема хранит enum с пустым
справочником, не заменяет адрес свободной строкой. houseNumber/buildingNumber
остаются text, поскольку это обозначения дома/корпуса, а не числовые величины.
Жилой комплекс: при открытии показываются первые 6 подсказок; полный охват,
фильтрация по городу, пагинация, UUID и возможность собственного значения неизвестны.
Метро: наблюдаемые 3 позиции представлены 9 отдельными полями. Это фиксация
исследованного UI, не доказательство постоянного размера массива.
Контракт не описывает повторяемую группу с произвольной кратностью; обобщённая
модель nearestMetroStations и адресный объект требуют отдельного расширения/
реализации. Новых ключей контракта для этого не введено.
depends_on: street/house/building/townDistance/metro → settlement;
separate_rooms → rooms; monthly_rent → currency. Циклов нет.
when для ветви 2+ комнат и Минска не задан: неизвестные коды запрещено подменять
подписями или 0/1. Условия подробно приведены выше и в description Option.
Жилой комплекс не объявлен зависящим от settlement: доступен и до адреса.
Направление и метка карты наблюдались как элементы интерфейса/вычисляемые данные;
нативные редактируемые поля и формат координат не установлены, фиктивные
latitude/longitude не добавлены. Независимая адресная иерархия регион/район
как отдельные поля формы не доказана.

6. ПРИВЯЗКИ
Файл bindings содержит ровно 2 записи:
- realt.building_number → [id="location.buildingNumber"], set_value/value_equals.
  Проверено при выбранном населённом пункте: одно совпадение, ввод и очистка.
- realt.short_description → [id="description.shortDescription"], set_value/value_equals.
  Одно совпадение, временный ввод и очистка строки.
Это проверка клиентского ввода; совместимость с расширением/движком Автопоста,
серверная валидация и публикация не проверялись.
События input/change/blur отдельно не трассировались, поэтому events не заданы.
Наблюдаемые input id для прочих полей перечислены выше. Числовые значения
маскировались инструментом, проверку value_equals считать неизвестной.
Для bargain прямой check завершился ошибкой неизменившегося checked, хотя клик
подписи работает; без идемпотентного алгоритма binding не создан.
Для div-переключателей не установлены значения кодов и формальная проверка
selected_text_equals, поэтому choose bindings отсутствуют.
Для autocomplete нужны выбор точной подсказки, проверка ID и ожидание зависимостей.
Формат параметров такого sequence заданием не определён; он только кандидат.
Для TinyMCE нужна работа с iframe; скрытый textarea не является достаточной привязкой.
Files: upload_files/files_accepted не утверждаются без принятого файла.
Для YouTube/3D требуется преобразовать коллекцию ссылок в одно поле URL.
Платные поля, контакты и агентство требуют соответствующего доступа.

7. НАБЛЮДЕНИЯ, ВЫВОДЫ И НЕИЗВЕСТНОЕ
НАБЛЮДАЛОСЬ: 52 конечных поля/управляющих параметра схемы, включая 9 полей
трёх строк метро, 4 поля вложений/ссылок и 3 параметра выбора категории.
В схеме нет групп и choice: неизвестные коды оставлены пробелом явно.
