ПОДТВЕРЖДЁННЫЙ ПРОТОКОЛ GET /api/v2/create/suggest
brand -> model[]
brand + model -> year[] (id — внутренний код, title — год)
brand + model + year -> generation[]
+ generation -> body[]
+ body -> engine[], gear[], transmission[]; иногда сразу modification[]
+ engine + gear + transmission -> modification[]
У вариантов id и title, иногда image/is_popular. В схему идут только код/подпись.
Нативные JSON-типы id сохраняются; URL-контекст разрешается однозначно по строке.
Марки → модели → поколения вложены. Остальные характеристики плоские.
Годы/диапазоны не экспортируются. Область → город пока не восстановлена:
не создаём выдуманную область для видимого города.
Коды технических полей и отображаемые подписи не копируются из AV или других сайтов.

ПРИЁМКА ЭТОЙ ОСНОВЫ
JSON валиден, ID уникальны, ссылки дерева существуют, только разрешённые деревья.
Годы не сохраняются, личные значения HAR не экспортируются, неизвестные коды null.
Все 22 поля имеют binding needs_review; наличие API не поднимает статус до ready.
Фото не теряются из схемы; рекомендация 5 одновременно не выдаётся за max_items=5.
Начальный каталог и неполные ветви явно различаются; проблемы отражаются в отчёте.
Кузова/двигатели/приводы/коробки объединяются при обоих форматах ответа;
технические сочетания не перебираются. Модификации не входят в текущую приёмку.
Запросы возникают только по ручному Start, GET разрешён только на suggest.
Остановка, продолжение и ошибки не меняют AV.by и не приводят к публикации.

ДОРАБОТКА
Для полной приёмки нужны география/валюта/другие скрытые варианты и ветви без
поколений; фактические ограничения фото, DOM и отдельная проверка заполнения.
observed_scope_complete не означает полный сбор сайта, готовый маппинг или binding.
Перед интеграцией исследовательской 2.2 нужна самостоятельная задача runtime.

ОБНОВЛЕНИЕ 0.4.0
Поле «Интервал запросов, мс» доступно до и во время обхода.
20 мс — значение по умолчанию, 100 мс — прежнее, 0 — без дополнительной задержки.
Настройка сохраняется отдельно для каждого расширения и не меняет checkpoint.
Это минимальный общий интервал между началами запросов всех ветвей,
а не гарантия скорости: учитываются ответ сервера и сохранение данных.
Каждый успешный ответ накапливается в памяти. После ошибки или остановки в той же вкладке
успешные запросы текущей модели берутся из RAM-кэша, а не повторяются.
После закрытия вкладки или обновления расширения годы и кэш исчезают;
повторяется незавершённая модель, собранные варианты и готовые модели остаются.
При ошибке storage данные в памяти не заменяются старой копией при экспорте;
скачайте результат до закрытия вкладки.

ОБНОВЛЕНИЕ 0.5.0 — ПРОИЗВОДИТЕЛЬНОСТЬ ABW
В последнем пользовательском результате: 32352 запроса, 830 готовых моделей,
21754 наблюдения, 4462457 байт компактного checkpoint. В версии 0.4.0
полный snapshot записывался после каждого ответа, что создаёт лишнюю нагрузку.
Теперь промежуточные записи объединяются: не чаще одной полной записи в 2 с
при поступлении ответов. Границы моделей, Stop и обработанная ошибка всегда
принудительно сохраняются. При аварийном закрытии возможен повтор последних
несохранённых ответов; годы и незавершённая позиция по-прежнему только в RAM.
Одновременные ветви: 1–5, по умолчанию 3; настройка со следующего запуска.
Параллельны только независимые годы одной модели; зависимости внутри года
проходятся последовательно. Никакие годы или технические варианты не пропускаются.
При ошибке новые ветви не запускаются; уже начатые ответы учитываются до
финального checkpoint. Stop отменяет все активные HTTP-запросы.
Интервал старта общий для всех ветвей; рост числа ветвей не умножает его лимит.
Параллелизм ограничен ответами сервера, браузером и сохранением данных;
измеренного ускорения на живом ABW нет. AV.by в этом обновлении не изменялся.

Импорт не допускает потери ранее завершённых моделей, даже если requests больше.
