Kufar: исследование продажи легковых автомобилей с пробегом
===========================================================

Это отдельное исследовательское приложение на Node.js (версия проекта >=22.13).
Оно не импортируется бэком, фронтом или расширением и не меняет их поведение.
Дополнительные пакеты, Selenium, Python и доступ к профилю Chrome не нужны.

Источники найдены в Network реальной формы подачи Kufar:
  /insertion/v1/meta/bootstrap?application=ad_insertion&category=2010&company_ad=0...
  /catalog/v1/nodes?tag=category_2010&view=taxonomy
Следующие запросы строятся из value предыдущего ответа, не из придуманных slug.
Проверенный в UI образец: Kia -> Rio -> IV Рестайлинг, состояние «С пробегом».
Сборщик получает все доступные марки/модели/поколения этой категории, без отбора
по году, количеству объявлений или популярности. Каталог общий для формы;
ограничение «с пробегом» отражено полем condition и областью задания.
По уточнению пользователя childOptions используется для двух цепочек:
марка -> модель -> поколение и регион -> город/район. Остальные перечисления
сохраняются массивами options, применимость условных полей — в Option.when.

Весь процесс одной командой из корня репозитория:
  node scripts/research/kufar-cars/run.mjs
Сбор -> нормализация -> структурная проверка -> сравнение с источником -> отчёт.
Если полный обход уже закончен, пересобрать результат без сетевых запросов:
  node scripts/research/kufar-cars/run.mjs --normalize-only
Для изолированного нового снимка run.mjs принимает --directory и --output.
В output/evidence должен быть актуальный kufar-ui-sample.json, полученный из UI.

Отдельные этапы:
  node scripts/research/kufar-cars/collect.mjs
  node scripts/research/kufar-cars/normalize.mjs
  node scripts/research/kufar-cars/validate.mjs
  node scripts/research/kufar-cars/audit.mjs
  node scripts/research/kufar-cars/report.mjs
  node --test scripts/research/kufar-cars/research.test.mjs

Порядок обязателен: нормализация полного результата откажется работать, пока
catalog.complete=false. Для промежуточного исследовательского снимка допустимы:
  node scripts/research/kufar-cars/normalize.mjs --allow-partial
  node scripts/research/kufar-cars/validate.mjs --allow-partial
Или одной командой: run.mjs --normalize-only --allow-partial.
Такие файлы сохраняют options_complete=false на непроверенных ветвях и не
считаются завершённым каталогом. Для итоговой приёмки флаг не применять.

Пробный ограниченный запуск:
  node scripts/research/kufar-cars/collect.mjs --max-requests 5
Повторный запуск использует кэш и продолжает без повторных запросов. Лимит
считает только новые HTTP-попытки текущего запуска, включая 429/503.
Не запускать два сборщика одновременно с одним каталогом work.
Для нового актуального исследования использовать отдельный --directory,
а при программном вызове build({directory,output}) указать тот же каталог.
Повторное использование старого кэша — продолжение снимка, не обновление данных.

Сеть и устойчивость
------------------
Только GET публичных наблюдённых endpoint, без cookies, токенов и обхода входа.
Запросы последовательные, интервал начала >=1100 мс (минимум --interval 1000).
При 429/503 учитывается Retry-After, максимум три попытки, затем остановка.
Другие HTTP-ошибки, неверный JSON/структура, перенаправления и таймаут 30 секунд
останавливают обход. Исправление причины и повторный запуск продолжат по кэшу.
Ctrl+C завершает после текущей операции; уже полученные ответы сохранены.
Не ускорять обход параллельными процессами и не обходить CAPTCHA/авторизацию.

work/kufar-cars-used/ (игнорируется Git):
  cache/<sha256-url>.json — URL, время, данные и checksum каждого ответа;
  catalog.json — атомарно сохраняемый прогресс;
  metadata.json — публичная конфигурация формы, без HTTP-заголовков/HAR.
Непосещённый список не равен успешно полученному пустому списку.

Результат data/parsing/cars_used_sale/:
  cars_used_sale_kufar.json — Category[] 2.2, исходные коды и childOptions;
  binding_cars_used_sale_kufar.json — по записи на поле, без дерева-дубликата;
  report_cars_used_sale_kufar.txt — наблюдения, ограничения и приёмка;
  evidence/ — исходный каталог, метаданные, DOM-наблюдения, счётчики и hashes.

normalize.mjs не делает этап B: нет common, межплощадочного mapping, finalId
или догадок по одинаковым названиям. Промежуточные уровни дерева имеют свои
ID и доступны для будущего прямого маппинга; поколение не обязано быть известно.

Границы достоверности
--------------------
Каталог собирается автоматически для всех ветвей. DOM проверен только на Kia
Rio IV Рестайлинг, как указано в задании; прохождение остальных моделей в UI
не заявляется. Источником прочих перечислений служат insertion metadata.
Фото и контакты требуют входа. Авторизованное ревью 2026-11-12:
evidence/kufar-authenticated-review.json. Подтверждены лимит 30 фото,
disabled имя/телефон из профиля, отсутствие email, radio способа связи,
поля обмена и торга. Имя/телефон/email — unsupported в проверенной форме.
Начальная проблема со щелчками обойдена через DevTools того же Chrome.
evidence/kufar-authenticated-interactions.json — завершённые проверки всех семи
оставшихся рецептов: 42 ready, 0 needs_review, 3 unsupported (данные профиля).
Для фото проверены оба input, HTTP 200, серверные картинки и счётчик 2 из 30.
Промежуточный непринятый JPEG отражён в evidence: несовпадение количества не успех.
В контракт 2.2 добавлен verify.target для отдельного элемента чтения выбранного
chip/radio; checkbox проверяется через native input.checked. Полная замена
multi_enum: replace_set + commit + selected_text_set_equals после повторного
открытия popup; проверены замена, повтор, очистка. DOM-рецепты сохранены в evidence,
но не выдаются за уже работающий обработчик расширения.
Данные 2.2 не подключать автоматически к runtime недвижимости версии 1.2/2.1.

Тесты проверяют изоляцию родителей, исходные ID, пустые/неполные ветви,
возобновление без сети, повреждённый кэш, rate configuration, полноту binding,
ссылки when, циклы зависимостей и запрет попадания новых автомобилей в scope.
