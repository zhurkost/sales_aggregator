# DaData через Cloudflare

Схема: браузер → Spring на VPS → Cloudflare Worker → DaData. Angular, профили,
карточки, SQLite и приватные справочники остаются на VPS. Worker передаёт только
текст адресного поиска и число подсказок. Containers и перенос базы не нужны.

## Настройка

1. В `wrangler.jsonc` указать фактический исходящий IP VPS в `ALLOWED_SOURCE_IP`.
2. Развернуть Worker: `npx wrangler deploy --config ops/cloudflare-dadata-relay/wrangler.jsonc`.
3. Добавить Cloudflare Secrets через защищённый ввод CLI или панель:
   `DADATA_API_KEY` — ключ подсказок; `RELAY_TOKEN` — случайный токен не короче 32 символов.
   Например, `npx wrangler secret put RELAY_TOKEN --config ops/cloudflare-dadata-relay/wrangler.jsonc`.
   Не передавать значения в аргументах команд и не сохранять их в Git.
4. В `/etc/autopost/environment` (root, права 0600) задать `DADATA_RELAY_URL`
   с полным HTTPS-адресом `/suggest` и `DADATA_RELAY_TOKEN` с тем же значением,
   что у `RELAY_TOKEN` в Worker. Перезапустить Spring после установки JAR с поддержкой relay.
   В этом режиме `DADATA_API_KEY` на VPS не используется и может быть удалён из активного файла.
5. Проверить поиск и выбор подсказки в авторизованном кабинете, затем сохранение
   карточки. `/health` подтверждает доступность Worker, но не доступность DaData.

Неполная конфигурация relay останавливает запуск Spring. Без relay-переменных
остаётся прямое подключение через `DADATA_API_KEY`. При отказе Worker скрытого
перехода на прямое подключение или автоматических повторов нет; ручной адрес
можно сохранить. Для отката восстановить предыдущий серверный environment и JAR.

## Границы доступа

`POST /suggest` принимает только JSON `{ "query": "Минск ...", "count": 8 }`.
Нужны одновременно IP из `CF-Connecting-IP` и `Authorization: Bearer <RELAY_TOKEN>`.
Cloudflare задаёт `CF-Connecting-IP`; входящий произвольный заголовок клиента
не считается способом авторизации. Без IP или секрета доступ закрыт.

Worker всегда обращается к одному endpoint DaData, ограничивает страну Беларусью,
проверяет длину запроса и размер ответа, не следует перенаправлениям, не принимает
адрес upstream от клиента и возвращает только нужные адресные поля. CORS не включён.
Spring сохраняет изоляцию кабинетов, короткий кэш, лимиты частоты и паузу при 429/5xx.
Worker не хранит запросы; логи observability отключены. Ключи и ответы с ошибками
провайдера в клиент не передаются. Запросы всё равно учитываются в квоте DaData
и Cloudflare Workers; исчерпание бесплатной квоты не обходится.

## Проверки

`node --test ops/cloudflare-dadata-relay/worker.test.mjs` проверяет авторизацию,
границы тела, фиксированный upstream, фильтрацию данных, ошибки и отсутствие повторов.
`npm run test:backend` проверяет настройку обоих режимов и существующую обработку адресов.
Живая проверка выполняется с VPS и через API кабинета: поиск → выбор → сохранение → чтение.
Публичный запрос к `/suggest` с другого IP должен получить 403; с VPS без токена — 401.
