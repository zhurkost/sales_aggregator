# Площадки для продажи автомобиля в Беларуси

Проверено 26.10.2026. Область исследования: размещение объявления о продаже одного легкового автомобиля. Проверялись публичные страницы самих площадок, справка, правила и документация импорта. Аккаунты не создавались, объявления не отправлялись. Это обзор доступных каналов, а не рейтинг по посещаемости или доле рынка.

## Вывод для MVP

Основной набор для белорусского продавца: **av.by, Куфар Авто, Автобарахолка Onlíner и ABW**. Дополнительные каналы: **Flagma Беларусь** и **Дром с белорусскими городами**. Наличие автомобилей в выдаче подтверждает работу площадки, но не показывает ее охват и вероятность продажи.

Единого общедоступного API, который разрешал бы частному пользователю немедленно опубликовать объявление во всех этих сервисах, не обнаружено. Подтверждены официальные механизмы файлового импорта у Kufar, Flagma и Дрома. Они требуют подключения или действий в кабинете. Для остальных каналов MVP должен готовить объявление и помогать продолжить размещение на самой площадке; успешное создание локального задания нельзя показывать как состоявшуюся публикацию.

## Kufar: что необходимо для реального импортера

Для обычной подачи есть [официальная пошаговая инструкция](https://helpcenter.kufar.by/knowledge_base/item/274990?sid=58788). [Правила размещения в редакции 26.10.2026](https://www.kufar.by/docs/agreements-and-rules?pageId=rules) требуют цену в BYN, запрещают телефон и внешние ссылки в описании, а также дубли одного автомобиля. Это нужно проверять до подготовки вариантов текста.

Первичный источник — [документация KML revision 5](https://import-docs.kufar.by/import_documentation_revision_5.html). Копия для разработчика: `docs/sources/kufar-import-official.html`; выделенная секция легковых автомобилей: `docs/sources/kufar-auto-section.html`.

- Структура: XML UTF-8 → `uedb` → `records` → `record`; категория легкового автомобиля `2010`, тип `sell`.
- Общие обязательные поля: `unid`, `area`, `region`, `remuneration_type`, `subject`, `body`, `category`, `type`, `phone`, `price`, `currency`, `contact_person`.
- В HTML автомобильного раздела помечены `required`: `cars_type`, `condition`, `cars_gearbox`, `mileage`, `regdate`, `cars_engine`, `cars_capacity`, `cars_brand_v2`.
- `cars_model_v2` и `cars_gen_v2` — зависимые параметры. Значения брать из [официальной таблицы](https://docs.google.com/spreadsheets/d/1OO8BW9c1ItjbWXzHoYxvK68cdVYTSn7rTno1MYshXfM/edit?usp=sharing), не конструировать из произвольного текста. [Справка по марке/модели](https://helpcenter.kufar.by/knowledge_base/item/368061) показывает пример MINI/Cooper.
- Фото: `photos` → `photo picture="https://..."`; требуется доступность оригиналов по сети. Ссылки `blob:` из браузера и пути с компьютера импорт не обслуживают.
- `unid` должен оставаться неизменным при обновлении. Исчезновение записи из подключенного файла означает удаление объявления; нельзя выдавать неполный фид за полный.

Справка содержит расхождение по частоте: revision 5 говорит об обработке раз в сутки, [более свежая статья об отчетах от 21.07.2026](https://helpcenter.kufar.by/knowledge_base/item/366748) указывает три обновления в сутки для фидов до 1000 позиций включительно и одно — для больших. Интерфейс MVP должен показывать ожидание импорта и не обещать мгновенного результата.

Наличие валидного XML еще не подтверждает принятие объявления: нужны подключенный профиль, доступный фид/фото, корректные справочники и успешная модерация. Испытание отправки в реальный аккаунт в рамках исследования не проводилось.

## Что не включено в доступные каналы

`avtobazar.by`, `autobazar.by`, `abz.by` и `myauto.by` проверялись как кандидаты. Через доступный исследовательский инструмент действующую форму публикации подтвердить не удалось. Это не означает, что домены закрыты. До отдельной проверки их нельзя показывать с активной галочкой «готово к размещению».

Социальные сети и Telegram-группы не включены в основной набор: наличие конкретного сообщества, допуск объявления и права на публикацию необходимо подтверждать для каждого канала отдельно. Автосалоны с собственным складом не приравнивались к открытым доскам объявлений.

## Поведение продукта

1. Одна карточка автомобиля, собственные фото, достоверные характеристики, цена и контакт продавца.
2. ИИ редактирует формулировки по введенным данным; не добавляет неподтвержденные «не бит», «не крашен», «один владелец», комплектацию или историю обслуживания.
3. Для каждой площадки показан режим: подготовка, подтвержденный файловый импорт после подключения, либо ручное завершение.
4. Авторизация, SMS и CAPTCHA выполняются пользователем на официальной площадке. Проверки и лимиты не обходятся.
5. Статусы различают подготовку, ожидание действий, отправку, модерацию и опубликованное объявление. Последний статус требует подтверждения площадки или отдельного явно обозначенного подтверждения пользователя.
6. После продажи система должна снимать объявления с подключенных каналов, учитывая семантику удаления из полного фида.

Это дает полезный MVP сразу и оставляет честный путь к полной автоматизации через официальные партнерские подключения. Для обещания «на всех доступных площадках автоматически» недостаточно одного ключа ИИ API.
