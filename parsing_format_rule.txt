ФОРМАТ РЕЗУЛЬТАТОВ ПАРСИНГА
Документ: parsing_format_rule.txt
Версия: 1.2 | Дата: 2026-11-01

Этот файл определяет структуру данных. Порядок работы — в parsing_rule.txt,
особенности конкретного задания — в parsing_input.txt. Это спецификация,
а не утверждение о наличии реализованного парсера или загрузчика.

1. CATEGORY И OPTION

Корень файла категории — массив Category[]. Все указанные свойства обязательны:

interface Category {
  id: string;
  name: string;
  description: string;
  categories: Category[];
  options: Option[];
}

interface Option {
  id: string;
  name: string;
  description: string;
  type: OptionType;
  fill_rule: FillRule;
  options: Option[];
}

id — стабильный машинный идентификатор; name — название для человека.
description может быть пустой строкой; categories/options всегда массивы.
Категории размещаются только в categories. У Category нет type и fill_rule.
Автоматическое наследование полей родительской категории не подразумевается.
Category.id уникален в каталоге; Option.id — во всём дереве одной категории.
Ссылки на поля разрешаются по id в пределах категории, включая группы.

Типы исходных полей площадки:
  group      — группа полей; options содержит поля или другие группы;
  text       — текст, включая телефон, VIN и артикул с ведущими нулями;
  integer    — целое число;
  number     — дробное или целое число;
  boolean    — true/false;
  date       — дата YYYY-MM-DD;
  datetime   — дата/время ISO 8601 с часовым поясом;
  enum       — один вариант из options;
  multi_enum — несколько вариантов из options;
  choice     — вариант перечисления; его код хранится в fill_rule.value;
  files      — коллекция ссылок на фотографии, видео или документы.

У enum/multi_enum дочерние элементы — choice. У остальных конечных полей
options = []. Реальные значения объявления не записываются в схему.
В общем файле обычные конечные поля имеют type = "text", вложения — "files",
группы — "group". Варианты площадки переносятся в маппинг, а не теряются.

2. FILL_RULE

Свойства необязательны, кроме value у choice. Использовать только применимые:
  value_from    — путь к данным: listing.price, attributes.memory, attachments.images;
  value         — постоянный код choice или иное явно заданное скалярное значение;
  required      — true/false; null, если обязательность пока не установлена;
  default_value — только явно установленное значение при отсутствии данных;
  transform     — упорядоченный список преобразований;
  depends_on    — массив id полей, которые должны быть обработаны раньше;
  when          — условие применимости;
  overwrite     — if_empty (по умолчанию), always или never;
  validation    — ограничения по разделу 4;
  file_role     — только files: product_image, product_video, product_document
                  либо другая явно описанная роль;
  file_policy   — только files: keep_original: true, ordering: "preserve_source",
                  primary: "explicit" (если нужна обложка),
                  on_incompatible: "needs_review". Свойство необязательно.

value_from — путь через точки, без выражений, индексов и буквальных точек
в ключах. Задавать его только при известном соответствии данным объявления.
value и value_from взаимоисключающие. Для files запрещены value/default_value.
Значения 0 и false не равны отсутствию. null — неизвестность/отсутствие,
а не команда очистить поле. Неизвестную обязательность не заменять false.
Для required: true пустая строка/коллекция не удовлетворяет требованию;
для boolean допустимо как true, так и false.

Разрешённые transform: trim, decimal_dot, to_number, to_integer, uppercase,
lowercase. Ошибка преобразования не заменяется приближением или округлением.
В общем text-поле результат остаётся строкой; преобразование в тип площадки
задаётся маппингом. Для files эти transform не применяются.

3. УСЛОВИЯ WHEN

Узел условия — одна из форм:
  {"all": [условия]} | {"any": [условия]} | {"not": условие}
  {"option_id": "id поля", "operator": "операция", "value": значение}

Операции: equals, not_equals, in, not_in, exists, gt, gte, lt, lte.
Для in/not_in value — массив скалярных значений; для exists value не нужно.
Сравниваются нормализованные значения, для enum — коды choice.value.
Числовые сравнения требуют числа, а не строки с цифрами. При переносе условия
в общую модель нужно сопоставить id и значения; нельзя копировать коды сайта
в условие текстового поля без преобразования.

Неизвестность не становится истиной через not/not_equals. Поле применимо
только при истинном условии. exists при отсутствии значения возвращает false;
для files проверяет непустую коллекцию, но не успешность загрузки.
Неактивное поле не проверяется на обязательность. depends_on не должен иметь
циклов и ссылок на отсутствующие поля; порядок элементов не заменяет зависимостей.

4. VALIDATION

  text:       min_length, max_length, pattern, format (email/uri/phone);
  числа:      min, max, exclusive_min, exclusive_max, multiple_of;
  enum:       allow_custom_value;
  multi_enum: allow_custom_value, min_items, max_items, unique_items;
  date/time:  min_date, max_date в формате соответствующего типа;
  files:      min_items, max_items, mime_types, extensions,
              max_file_size_bytes, max_total_size_bytes,
              min_width_px, max_width_px, min_height_px, max_height_px,
              min_duration_seconds, max_duration_seconds,
              min_pages, max_pages, unique_items.

Указывать только подтверждённые и применимые ограничения. Неизвестное значение
можно обозначить null и пояснить в отчёте; это не отсутствие лимита.
Противоречивые границы и неподдерживаемые свойства требуют уточнения.
Ограничения площадки сохраняются в её Option, а не автоматически становятся общими.

5. ОСОБЕННОСТИ FILES

Files — обычный Option в тех же Category[] и маппингах. Его значение — массив
ссылок на исходные вложения (даже для одного файла), не строка и не дочерние Option.
value_from указывает на коллекцию данных объявления, например attachments.images.
Ссылки могут указывать на хранилище или внешний URL, если площадка его принимает.
Бинарные данные, реальные файлы и upload-токены в результаты парсинга не включать.

Роль определяет смысл: фото товара и скан документа — разные поля.
Ограничения файлов описываются через validation; подготовка под сайт — в маппинге.
Оригиналы сохраняются. Порядок и главное изображение должны быть определены явно;
обрезка, потеря файлов и выбор первых N вместо превышения лимита не подразумеваются.
Загрузка/ввод URL и проверка принятия — задача привязки страницы, не парсинга.

6. ФОРМАТ МАППИНГА

Корень: {category_id, platform, fields: []}.
Запись fields: {common_option_id, platform_option_id, conversion}.
Если преобразование требует нескольких входов, вместо common_option_id
использовать common_option_ids: [id, ...] и явно описать их назначение.
Все ссылки должны разрешаться в соответствующих файлах категорий.

conversion описывает направление из общей модели в формат площадки:
  kind = "identity" — перенос без преобразования;
  kind = "lookup"   — values: [{from, to}, ...], точные коды площадки;
  kind = "files"    — preparation: {operations: [...]}, подготовка коллекции.

Для lookup без соответствия: on_unmapped = "needs_review".
Для files без допустимой подготовки: on_incompatible = "needs_review";
operations: [] означает перенос без изменения, если требования уже выполнены.
Разрешённые операции файлов задаются явно с kind и параметрами: resize_image
(max_width_px, max_height_px, keep_aspect_ratio), compress_image (пределы качества),
convert_image (mime_type), normalize_orientation. Неизвестные операции не исполняются.

Преобразования чисел, дат, единиц, списков и составных значений должны иметь
явные параметры: исходный/целевой формат, единицы, разделители или используемые
поля. Если конкретный обработчик/формат параметров не определён заданием,
описать необходимое преобразование в отчёте как кандидат, не выдумывать рабочий
код или исполняемую команду. Маппинг не считается автоматически обратимым.

7. ПРИВЯЗКИ К СТРАНИЦЕ

CSS-селекторы и действия браузера не входят в универсальный fill_rule.
Если задание требует привязки, описывать её отдельно:
  category_id, option_id, platform;
  target: {selectors: [...]};
  action: set_value/select_option/set_checked/choose/click/autocomplete/
          upload_files/sequence;
  events: [input, change, blur] — по необходимости;
  wait_for: [visible, enabled], timeout_ms;
  verify: {kind: value_equals/selected_text_equals/checked_equals/files_accepted}.

Селекторы и проверки должны подтверждаться страницей. Несколько совпадений —
неоднозначность, а не выбор первого. Для files одного input/change или preview
недостаточно: нужно подтверждение принятия площадкой. Парсинг не публикует объявление.

8. ПРИМЕРЫ

Сокращённая общая категория; ограничения отдельных сайтов здесь не подразумеваются:

[
  {
    "id": "cars",
    "name": "Легковые автомобили",
    "description": "Общие поля категории",
    "categories": [],
    "options": [
      {
        "id": "car.condition",
        "name": "Состояние",
        "description": "Состояние автомобиля",
        "type": "text",
        "fill_rule": {"value_from": "listing.condition"},
        "options": []
      },
      {
        "id": "product.images",
        "name": "Фотографии товара",
        "description": "Фотографии в выбранном порядке",
        "type": "files",
        "fill_rule": {
          "value_from": "attachments.images",
          "file_role": "product_image"
        },
        "options": []
      }
    ]
  }
]

Иллюстративный маппинг. example, vehicle_condition, vehicle_images и коды 1/2
условные; при реальном парсинге они должны существовать в источнике площадки:

{
  "category_id": "cars",
  "platform": "example",
  "fields": [
    {
      "common_option_id": "car.condition",
      "platform_option_id": "vehicle_condition",
      "conversion": {
        "kind": "lookup",
        "values": [{"from": "Новый", "to": 1}, {"from": "С пробегом", "to": 2}],
        "on_unmapped": "needs_review"
      }
    },
    {
      "common_option_id": "product.images",
      "platform_option_id": "vehicle_images",
      "conversion": {
        "kind": "files",
        "preparation": {"operations": []},
        "on_incompatible": "needs_review"
      }
    }
  ]
}
