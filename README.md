# Автопост — недвижимость

Приложение на Angular 21 и Spring Boot 3.5 / Java 17. После входа открывается раздел «Недвижимость» с вкладками «Аренда квартир» и «Продажа квартир». Выбранная вкладка сохраняется при обновлении страницы отдельно для каждого профиля в текущей вкладке браузера. При первом входе выбрана аренда.

## Возможности

- В обеих вкладках используется один редактор. Введённые данные и фотографии независимы и сохраняются в памяти при переключении. Для продажи редактор загружает собственный справочник: полную цену, валюту, характеристики квартиры и условия сделки. Кнопка «Проверить карточку» показывает подготовленные значения для выбранных площадок. Кнопка «Опубликовать» открывает формы выбранных площадок для текущего типа сделки.
- Заполнение карточки из описания с помощью ИИ, адресный поиск и фотографии.
- Подготовка и перенос значений на Kufar, Onliner, Realt и Domovita через расширение.
- Переходы после заполнения, подтверждение подачи и продвижение выполняет пользователь. Обновление вкладки площадки не запускает заполнение заново.
- Профили, вход и выход сохраняются. Ранее сохранённые контактные данные используются как значения по умолчанию для новых карточек.

Универсальный редактор товаров, общий список объявлений, очередь, управление профилем и командой, массовая загрузка/редактирование, справочник площадок и интеграции удалены из интерфейса и серверного API. Исторические данные SQLite не удаляются. Проверки прав доступа к существующим общим кабинетам сохраняются для совместимости с активными сессиями.

## Запуск и проверки

Нужны Node.js 22.13+ и JDK 17+ (JAVA_HOME).

~~~sh
npm ci
npm --prefix frontend ci
npm run dev
npm test
npm run test:frontend
npm run build
node scripts/package-angular-spring.mjs
~~~

Адрес разработки: http://127.0.0.1:5173. Backend-сборка выполняет clean, чтобы удалённые классы и старый каталог не попали в JAR. Генерация универсального domain.json и зависимость ExcelJS удалены.

Архив релиза: work/autopost-angular-spring.tar.gz. Публикация в Git сама по себе не обновляет VPS. Перед развёртыванием выполняется проверенная резервная копия SQLite.

### Сквозная браузерная проверка

После `npm run build` установите тестовый Chromium командой `npx playwright install chromium` и запустите `npm run test:browser`. Проверка использует собранный Angular, настоящий Spring API с временной БД и настоящее расширение в отдельном профиле браузера. Она проверяет сохранение вкладки, перенос значений продажи, замену старых фото, продолжение после ручного перехода между шагами и отсутствие автозаполнения после обновления страницы площадки. Форма Onliner подменяется локальной тестовой страницей; это не проверка актуальной разметки сайта.

`node scripts/test-browser.mjs --live` открывает настоящие формы четырёх площадок без авторизации в аккаунтах пользователя и сохраняет наблюдения в `work/browser-tests`. Доступные поля проверяются до окончательной отправки; авторизация и подтверждение телефона остаются ограничениями такого прогона. Диагностика находится только в тестовом процессе и не включается в приложение или расширение.

Готовые сценарии находятся в `tests/browser/scenarios`: например, `node scripts/test-browser.mjs --case=tests/browser/scenarios/sale-byn-multiple.json`. Формат сценария задаёт категорию (`deal`), адрес, значения основных полей (`fields`), дополнительных (`extras`), количество фото и выбранные площадки. Сценарий вводит значения через интерфейс, сохраняет ответ подготовки и фактические значения контролов. `--delayed-form` проверяет открытие тестовой формы через 75 секунд. `--inspect-form` создаёт временную диагностическую копию расширения и сохраняет его внутренний прогресс; исходное расширение не меняется.

Фото по ссылкам сначала загружаются кнопкой «Загрузить фото по ссылкам». Загружаются только изображения HTTPS, до 20 МБ; общий лимит — 12 фото. Загрузка выполняется браузером без отправки учётных данных на источник. Если источник запрещает загрузку через CORS, интерфейс предлагает скачать файл и добавить его кнопкой «＋ Фото». Перед запуском пользователь видит превью; ссылки без загруженных файлов не передаются как будто фотографии уже готовы.

Сценарии `sale-realt-partial-photo-failure.json` и `rent-realt-photo-failure.json` проверяют сбой загрузки фото. Только в тестовом браузере запрос загрузки Realt получает HTTP 503: для продажи после первого успешного файла, для аренды — для всех файлов. Проверка требует, чтобы непринятые фото оставались в списке незаполненных полей. Фактическое принятие определяется по непустым `media.photos.N.uuid`, а не по `input.files`. Настройки перехвата не входят в приложение или расширение. Журнал `network.json` содержит только методы, адреса без параметров и типы содержимого запросов.

## Устройство проекта

- frontend/src/app/rental — редактор, адреса, ИИ, фотографии и задания аренды.
- backend/src/main/java/by/autopost/rental — общая подготовка карточек недвижимости и распознавание описаний с учётом типа сделки.
- backend/src/main/java/by/autopost/workspace — сервис учётных записей и репозиторий; HTTP-слой не содержит SQL.
- backend/src/main/java/by/autopost/address — интерфейс адресного провайдера и HTTP-адаптер DaData.
- data/rental/categories.json — реестр идентификаторов для /api/workspace/categories/{category}/…, комплектов справочников, правил ИИ и публикации.
- data/rental/apartments_long_term_rent — версионируемые схемы и правила четырёх площадок.
- data/rental/apartments_sale — активный комплект продажи: поля редактора, справочники и правила подготовки для тех же четырёх площадок. Источники и протокол разбора — в data/parsing/apartments_sale.
- lib/workspace.ts — сессия, связь с расширением и обработка фото.
- extension — расширение для четырёх площадок аренды и продажи; старые адаптеры, протоколы и универсальные справочники удалены.

Разделение слоёв и принятые ограничения описаны в архитектуре. ArchUnit и проверки импортов TypeScript контролируют границы при обычном запуске тестов и в CI.
