КОМПАКТНАЯ КАРТОЧКА И ЗАПОЛНЕНИЕ ИЗ ОПИСАНИЯ
2026-11-02

Основной экран: описание, единый адрес, семь главных параметров, выбранные
площадки. Нет раскрывающихся групп и повторяющихся пояснений под полями.
Редкие параметры доступны в одной панели с поиском и фильтром «Заполненные».
Карточка по-прежнему хранит весь набор канонических фактов; новые поля и
площадки подключаются через приватный реестр и планы подготовки.
Мои квартиры и просмотр подготовленных данных используют ту же панель.

Кнопка «Заполнить с ИИ» использует POST /api/workspace/rental/analyze.
Требуются сессия профиля, текущий кабинет и актуальная версия схемы.
OpenRouter вызывается сервером с уже настроенным ключом и моделью. В запрос
передаются только введённое описание, канонические поля и допустимые значения.
Данные других карточек, приватные исходные схемы площадок и ключи в клиент
не передаются. Ограничение запроса: 10–8000 символов, 10 запросов/минуту
на профиль, таймаут провайдера 45 секунд. Фото этот метод не анализирует.

Ответ проверяется по актуальной схеме: неизвестные поля, неверные типы,
недопустимые варианты и отсутствующие в тексте цитаты отбрасываются.
Числовое значение должно встречаться в цитате; числа JSON и десятичные строки
нормализуются в точные строки. Пустые значения, false и ноль различаются.
Свободный текст должен быть взят из цитаты; исключение — предлагаемый заголовок.
Даты принимаются только как явно указанный ISO-день. Телефоны требуют цифр
исходного номера. «Рубли» без уточнения валюты не означают автоматически BYN.
Проверки ограничивают ошибки модели, но не доказывают смысл каждого enum/boolean:
пользователь проверяет результат, а значок ✦ показывает исходную цитату.

ИИ заполняет пустые поля. Отличия от введённых значений применяются только
после выбора пользователя. Предлагаемый адрес не считается подтверждённым
геокодером. Его зависимые факты применяются вместе с адресом; ручная смена
адреса отменяет старые отложенные предложения. Поздний ответ после смены
карточки, схемы или редактирования не применяется. При ошибке сохраняются
описание и ручные значения. Заполненное автоматически сохраняется обычным
механизмом ревизий. Метод анализа не публикует и не изменяет внешние объявления.

Проверка: frontend rental-ai.spec.ts, backend RentalAiTest и авторизация
WorkspaceIntegrationTest; независимые проверки гонок и адресных зависимостей.
Живой запрос к OpenRouter проверяется только на синтетическом описании.
Пробелы интеграции публикации, описанные в rental-card-v2.txt, сохраняются.
