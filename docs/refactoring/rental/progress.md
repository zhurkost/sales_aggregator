Решения:

- Чтение отдаёт карточку как сохранена, без подстановки текущей `schemaVersion`. Раньше

  отвяжет версию карточки от селекторов, и это станет редкостью.
- «Обновить поля карточки» (`POST normalize`, адрес не менялся) для карточки модели 2

- Подготовка сама держит два правила, которые раньше обеспечивала миграция при чтении:
  адресные значения в `values` берутся только из `address`, `extras` не читаются (их
  всегда обнуляли).
- Команда: явные `--database` и `--rental-reference` (как у валидатора, тестируемо);
  несуществующую базу не создаёт, базу без `rental_drafts` не меняет; каждая карточка —
  ревизия +1 с проверкой ожидаемой, время сохранения не меняется (порядок «Мои квартиры»),
  до трёх попыток при одновременном сохранении, нечитаемые строки не трогает и
  перечисляет id; ключ `extras` удаляет. В `deploy-release.sh` запускается от `autopost`
  (`runuser`), чтобы файлы WAL/SHM SQLite не стали принадлежать root, и только если база
