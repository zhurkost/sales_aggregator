# Фаза 1A — исправления во фронтенде и расширении

Цель: закрыть подтверждённые баги, которые чинятся без изменения Java-кода, и сделать подачу
безопасной по умолчанию. Архитектуру в этой фазе не перестраиваем.

Проверка: `npm test` и `npm run test:frontend`. Java-код в этой фазе **не трогать**.

## Задачи

### 1. Починить красный master

`frontend/src/app/rental/rental-publication.spec.ts` ждёт текст «0.9.1», а компонент требует
расширение 0.9.2 (`extension/core.js`, `VERSION`).

- Вынести требуемую версию расширения для аренды в одну константу фронтенда
  (например, `REQUIRED_EXTENSION_VERSION` рядом с `rental-publication.component.ts`).
  Её используют и сообщение об ошибке, и ссылка «Скачать расширение …» в шаблоне.
- Тесты проверяют константу, а не литерал версии.
- Приёмка: `npm run test:frontend` зелёный.

### 2. Подача по умолчанию — только помощник

Сейчас `mode = "automatic"` по умолчанию (`rental-publication.component.ts`), и на Kufar
расширение само нажимает «Подать» даже при замечаниях проверки (`extension/rental-page.js`,
блок `task.mode === "automatic"`).

- Режим по умолчанию — `assist`. Флажок «Автоматически пройти шаги формы» по умолчанию снят.
- Расширение выполняет финальную подачу, только если одновременно `mode === "automatic"`
  и у задания `job.dataReady === true`. Сервер этого поля пока не присылает (его добавит
  фаза 1B), поэтому до 1B автоподача фактически выключена. Отсутствующее поле — `false`.
- При включении флажка — короткое подтверждение: «Расширение само нажмёт „Подать“ на
  площадках, где проверка прошла без замечаний. Платные услуги и CAPTCHA остаются за вами».
- В `extension/rental-core.js` `validate()` пропускает булево `dataReady` у задания и
  отклоняет другие типы.
- Тесты: в `extension/tests/rental.test.cjs` — подача не происходит без `dataReady` и в режиме
  `assist`; происходит только когда оба условия выполнены. Во фронтенде — режим по
  умолчанию `assist`.

### 3. Описание на Domovita (TipTap) искажается

Сервер готовит описание как HTML (`plain_text_html`: `&amp;`, `&quot;`, `<br>`, `<p>`).
`extension/rental-form.js`, ветка `richtext`, вырезает теги регуляркой и пишет `textContent`:
сущности остаются буквально, переносы строк теряются, а редактор TipTap/ProseMirror
может не увидеть изменение.

- Добавить функцию, которая превращает подготовленный HTML обратно в текст:
  `<br>` → `\n`, границы `<p>` → пустая строка между абзацами, HTML-сущности декодируются
  через `DOMParser` (не регуляркой). Других тегов сервер не порождает — неизвестный тег
  оставлять как текст нельзя, его нужно отбросить.
- Вставлять текст в `contenteditable` как пользовательскую вставку: сфокусировать элемент,
  выделить содержимое, отправить `ClipboardEvent('paste')` с `DataTransfer` типа `text/plain`.
  Если редактор не принял вставку (текст не изменился), запасной путь —
  `document.execCommand('insertText', false, text)`. Прямое присваивание `textContent` убрать.
- Признак «заполнено» — нормализованный текст редактора совпадает с ожидаемым текстом
  (с учётом переносов).
- Тесты: описание с `"кавычками"`, `&`, `<script>` в тексте и двумя абзацами переносится без
  сущностей и с сохранёнными переносами; поле, которое пользователь уже изменил, не трогается.

### 4. Правка адреса не должна стирать «Рядом с домом»

Сейчас каждое нажатие клавиши в поиске адреса (`address-input.component.ts`, `search()`)
сообщает новый адрес, а `rental-editor.component.ts` (`addressChanged` → `replaceAddress`)
удаляет все `card.addressDependentFacts` (метро, ЖК, микрорайон, расстояние).

- Зависимые сведения сбрасываются только когда **подтверждённый дом** меняется на другой
  подтверждённый дом или пользователь явно очищает адрес. Ввод текста в поиск и ручное
  редактирование частей адреса их не трогают. Координаты и `addressBoundFields` по-прежнему
  сбрасываются при любой смене адреса (это отдельные сведения).
- При сбросе показать строку «Сброшены сведения рядом с домом: …» с кнопкой «Вернуть»,
  которая восстанавливает прежние значения одной операцией (до следующего изменения адреса).
- Учесть новый поток ИИ-адреса (`rental-ai.assistant.ts`, `acceptAiAddress`, `enrichLiteral`):
  принятие предложенного ИИ адреса работает по тем же правилам.
- Тесты: набор текста в поиске не стирает метро; выбор другого подтверждённого дома стирает
  и показывает «Вернуть»; «Вернуть» восстанавливает значения; очистка адреса стирает.

### 5. Не перечитывать список карточек после каждого автосохранения

`rental-draft.store.ts`, `save()`, вызывает `refresh()` после каждой записи, а сервер при этом
разбирает JSON всех карточек кабинета.

- После успешного сохранения обновлять элемент списка локально (заголовок
  `listing.title`, адрес `address.label`, ревизия). Если элемента нет — добавить.
- Полный `refresh()` — при загрузке редактора и при открытии панели «Мои квартиры».
- Тест: серия правок даёт столько запросов `drafts/<id>`, сколько сохранений, и ни одного
  `GET drafts` между ними; счётчик «Мои квартиры» остаётся верным.

### 6. Ошибка без JSON не ломает сообщение

`rental-api.ts` всегда вызывает `response.json()`. На HTML-странице 502/504 от nginx
пользователь видит «Unexpected token <».

- Читать тело как текст, пробовать разобрать JSON; если не вышло — понятное сообщение
  «Сервер временно недоступен (код N). Изменения сохранятся при следующей попытке.»
- Тест для 502 с HTML-телом и для пустого тела.

### 7. Конфликт версий: дать выйти из цикла

После 409 каждая следующая правка снова уходит со старой ревизией и снова падает.

- Пока карточка в состоянии конфликта, автосохранение не отправляет запросы.
- Рядом с «Сохранить копию» — «Загрузить сохранённую версию»: после подтверждения
  отбрасывает локальные правки и открывает серверную ревизию.
- Тесты: после 409 новые правки не порождают запросов `drafts/<id>`; оба выхода работают.

### 8. Клавиатура в адресных подсказках

`address-input.component.ts`: список подсказок нельзя выбрать с клавиатуры.

- Поле — `role="combobox"` с `aria-expanded`, `aria-controls`, `aria-activedescendant`;
  список — `role="listbox"`, варианты — `role="option"`.
- Стрелки вверх/вниз перемещают активный вариант, Enter выбирает, Escape закрывает список.
  Первый вариант автоматически не выбирается (это требование уже есть в тестах).
- Тесты на навигацию, выбор Enter и Escape.

### 9. Тестовый код вне боевого кода расширения

`extension/rental-form.js`, `visible()`: элемент считается видимым, если user agent содержит
«HappyDOM».

- Убрать эту ветку. В тестах подменять `getClientRects` (или передавать функцию видимости),
  чтобы поведение в тестах совпадало с браузером.
- Классы конкретных сайтов в `selected()` (`text-white bg-basic`, `chip__filled-green`)
  перенести в рецепт формы как необязательный ключ контрола `selectedClass` для тех
  площадок, где они нужны. Какие площадки — установить по `data/parsing/**/report_*.txt`
  и существующим тестам. Если установить нельзя — оставить как есть и записать в отчёт.

## Не делать в этой фазе

Не менять селекторы форм без доказательства из отчётов исследований.
