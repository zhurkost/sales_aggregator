# Фаза 4 — честное покрытие «подготовлено → заполнено»

Цель: система обещает только то, что реально переносит. Пример из ревью: у Realt 51 поле
в плане, а рецепт формы заполняет 24, без заголовка и описания; интерфейс пишет «Подготовлено».

## Задачи

### 1. Отчёт покрытия как часть комплекта

- Для каждой площадки вычислять (на сервере, при загрузке комплекта) таблицу:
  поле карточки → нативное поле → элемент формы → статус
  `transferred` | `prepared_only` | `deferred` (с причиной) | `constant`.
- Валидатор требует, чтобы каждое поле плана было либо привязано к элементу формы, либо явно
  помечено в плане как `transfer: "manual"` с причиной. Молча неперенесённых полей нет.
- Команда `--rental-coverage` печатает таблицу (markdown) — для PR и для владельца.
- Тест на реальном комплекте: каждое поле плана имеет статус; число `prepared_only` = 0
  (после того как все такие поля размечены как `manual` с причиной).

### 2. Интерфейс показывает правду

- Результат `prepare` для каждой площадки возвращает: что уйдёт в форму, что нужно ввести
  на площадке вручную (с причиной), какие замечания блокируют.
- Карточка платформы в «Проверке» показывает «Уйдёт в форму: N полей · Вручную на площадке: M».
- Поле карточки, которое ни на одной выбранной площадке не переносится и не нужно для
  подготовки, в редакторе помечается «пока не переносится» или скрывается в «Все параметры».
- `dataReady` переименовать в то, что оно значит (`checksPassed`), и не писать «Подготовлено»,
  если есть поля «вручную».

### 3. Realt: заголовок и описание

- Заголовок: в `research/…/realt/report_*.txt` перечислены наблюдаемые id полей
  (раздел описания, рядом с `[id="description.shortDescription"]`). Добавить контрол для
  `realt.title`, только если id прямо указан в отчёте. Нет — `transfer: manual` +
  вопрос в отчёте фазы.
- Подробное описание — TinyMCE в iframe (`description.description_ifr`). Добавить в
  расширение действие `iframe_richtext`: найти iframe по селектору, работать с его
  `contentDocument` (тот же origin), вставлять текст так же, как в фазе 1A (paste/insertText).
  Валидатор рецептов знает новое действие. Тест — на синтетическом iframe.
- Отметить в отчёте: требуется живая проверка на форме Realt.

### 4. Остальные `prepared_only`

Для оставшихся полей Kufar (7), Realt (около 30) и Domovita (9): привязать те, у которых
селектор и способ ввода подтверждены отчётами исследований; остальные — `transfer: manual`
с причиной. Список изменений — в отчёте фазы.

## Приёмка

`--rental-coverage` показывает 0 неразмеченных полей; интерфейс не обещает переноса
неперенесённого; тесты зелёные.
