# Фаза 1B — исправления на сервере

Цель: убрать узкие места и ошибки сервера, найденные в ревью, без смены архитектуры.
Требует сборки backend (`npm run test:backend`). Нет доступа к Maven Central — фазу не начинать.

## Задачи

### 1. Адресный поиск не блокирует всех пользователей

`AddressService.suggest` и `select` помечены `synchronized` и внутри ждут DaData
(до 10–12 с). С коммита 01a7e16 их же вызывает `RentalAiAddressResolver`.

- Перенести класс в `by.autopost.rental.address` (он нужен только аренде).
- Сетевой вызов выполняется вне блокировок. Под блокировкой — только чтение/запись кэша
  и счётчиков бюджета (или потокобезопасные структуры без общей блокировки).
- Разделить два кэша: результаты запросов (ключ — нормализованный запрос, **без** кабинета;
  ответ DaData одинаков для всех) и выданные подсказки (ключ — ID, с кабинетом владельца).
  У каждого свой предел размера и TTL; подсказки, выданные меньше 20 минут назад,
  не вытесняются чужими запросами.
- Суточный бюджет запросов к DaData настраивается свойством
  (`autopost.dadata-daily-limit`, по умолчанию 10 000) и даёт понятную ошибку 429.
- Тесты: два параллельных `suggest`, один из которых висит на медленном ответе, не блокируют
  друг друга (подменённый HTTP-клиент); подсказка не вытесняется потоком чужих запросов;
  повторный запрос из другого кабинета берётся из кэша; ID подсказки чужого кабинета
  по-прежнему отклоняется.

### 2. Список карточек без разбора JSON

`RentalDraftService.list` разбирает JSON каждой карточки, чтобы достать заголовок и адрес.

- Добавить в `rental_drafts` колонки `title` и `address_label` (ALTER TABLE, если колонки нет;
  заполнить из `data` для существующих строк при старте один раз).
- `save` записывает их из карточки; `list` читает только колонки.
- Тест: список не вызывает разбор `data`; старые строки получают значения после миграции.

### 3. Одинаковые лимиты входа

`/prepare` не ограничивает размер, `/normalize` и `/extension-config` — 250 000 символов.

- Один лимит размера карточки для `drafts/{id}`, `normalize`, `prepare`, `extension-config`
  (константа в одном месте). Ответ 413.
- Тест на каждый эндпоинт.

### 4. Сервер сообщает расширению, можно ли подавать автоматически

Фаза 1A научила расширение подавать только при `job.dataReady === true`.

- `RentalBrowserPreparation` добавляет в каждое задание `dataReady` из результата подготовки
  этой площадки.
- Тест: задание с замечаниями получает `dataReady: false`, без замечаний — `true`.

### 5. ИИ-подсказки не теряются из-за типографики

`RentalAiPolicy.grounded` сравнивает цитату с текстом без нормализации ё/е, кавычек и тире;
`validValue` отбрасывает код варианта, пришедший числом (2 вместо "2").

- Общая нормализация для сравнения: регистр, пробелы, ё→е, «»„“"″ → ", —–‑ → -, неразрывные
  пробелы → пробел. Применять к исходному тексту и к цитате.
- Число, совпадающее с кодом варианта перечисления, приводится к строке.
- Запрос к модели — со строгой JSON-схемой ответа (`response_format: json_schema`), если
  провайдер её поддерживает; иначе — как сейчас.
- Тесты на каждый случай.

## Не делать

Не менять модель карточки, формат справочников, раскладку пакетов кроме переноса
`AddressService`. Не трогать модуль обычных объявлений.
