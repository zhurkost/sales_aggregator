# Рефакторинг модуля «Аренда квартир»

Исходное ревью: [review.md](review.md). Общие правила: [AGENTS.md](../../../AGENTS.md).
Журнал выполнения: [progress.md](progress.md).

## Цель

Человек один раз заполняет карточку квартиры, и всё, что система обещает перенести,
действительно попадает в формы выбранных площадок. Код становится настолько простым,
что тот же подход можно перенести на обычные объявления.

Измеримые признаки готовности всего рефакторинга:

- для каждой площадки есть отчёт покрытия «поле карточки → поле формы → элемент формы»,
  и интерфейс показывает ровно его;
- логика применимости и подготовки существует только на сервере;
- в серверном коде аренды нет `JsonNode` за пределами разбора входа;
- на площадку приходится не больше двух рабочих файлов справочника;
- фото и история публикаций хранятся на сервере;
- автоматическая подача выключена по умолчанию и невозможна при замечаниях проверки.

## Целевая архитектура

```text
data/rental/apartments_long_term_rent/
  card.json                     модель карточки: понятия, типы, варианты, подписи, группы
  platforms/<id>/mapping.json   нативные поля формы + как их получить из карточки
  platforms/<id>/form.json      URL, шаги, элементы, действия расширения (бывш. browser_*.json)
research/rental/apartments_long_term_rent/<id>/   отчёты, исходные схемы, исследовательские файлы

backend  rental/model        records: Card, Address, Money, FieldDef, Mapping, Conversion (sealed), FormRecipe
         rental/catalog      загрузка и валидация комплекта один раз при старте
         rental/engine       применимость, проверка, подготовка, покрытие
         rental/application  сценарии: черновики, фото, публикации, ИИ
         rental/persistence  JDBC + миграции
         rental/web          контроллеры, DTO
frontend rental/            signals-store, HttpClient, компоненты только рисуют ответ сервера
extension rental-*.js       исполняет form.json, отчитывается серверу о статусе и ссылке
```

## Как запускать агента на фазу

Одна фаза — одна изолированная сессия агента. Шаблон задания:

```
Ты работаешь в репозитории sales_aggregator. Прочитай AGENTS.md, затем
docs/refactoring/rental/README.md и docs/refactoring/rental/phase-<N>-*.md.
Начни рабочую ветку от вершины ветки claude. Выполни все пункты фазы по порядку,
маленькими коммитами, с тестами. Не выходи за рамки фазы. В конце допиши отчёт
в docs/refactoring/rental/progress.md и перечисли коммиты.
```

## Общие критерии приёмки каждой фазы

- `npm test`, `npm run test:frontend`, `npm run test:backend` зелёные
  (backend — если фаза меняла Java и среда позволяет собрать).
- Валидатор справочников проходит.
- Каждое исправление закрыто тестом, который падал до исправления.
- Нет новых ключей JSON, которые не читает код; нет нового кода на сыром JSON.
- `progress.md` обновлён; `docs/rental-architecture.md` отражает фактическое состояние.
