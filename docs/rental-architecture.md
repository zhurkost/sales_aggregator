# Архитектура формы долгосрочной аренды

Текущая форма существует в памяти страницы Angular. Кнопки «Мои квартиры» и «＋ Новая» оставлены без действий. Данные и выбранные фотографии живут до закрытия, обновления страницы или выхода из профиля.

## Границы ответственности

| Область | HTTP | Прикладная логика | Данные / внешний адаптер |
|---|---|---|---|
| Учётная запись | WorkspaceController, Access | WorkspaceService | WorkspaceRepository → JdbcWorkspaceRepository |
| Аренда | RentalController | RentalCatalog, RentalPublicationService | ReferenceRepository → FileReferenceRepository |
| Адреса | RentalController | AddressService | AddressProvider → DadataAddressGateway |
| ИИ | RentalAiController | RentalAiService, RentalAiPolicy | AiGateway → HttpAiGateway, адресный сервис |

Access проверяет cookie, Origin и права на кабинет. Контроллеры не обращаются к SQL. Регистрация и выдача сессии выполняются в транзакции; cookie выставляется после успешного завершения. Обработка формы аренды не обращается к SQLite. Исторические записи базы при обновлении приложения не затрагиваются.

Сервер владеет схемами площадок, правилами применимости, проверкой значений, точным преобразованием decimal и сопоставлением вариантов. Angular получает отдельный EditorContract без исполняемых правил. ИИ использует серверную AnalysisSchemaBuilder. Преобразования общих значений в нативные выполняет PreparationEngine.

## Angular

- RentalFormStore — состояние формы, схема, локальный счётчик изменений, применимость и проверка.
- RentalFormEditor — изменения фактов, адресных зависимостей и выбранных площадок.
- RentalAiAssistant — получение и принятие предложений, защита от поздних ответов.
- RentalViewModel — подписи, фильтрация и отображение серверных результатов.
- Компоненты — шаблоны, пользовательские события, доступность и фокус.
- Gateway — обращения к HTTP и расширению. RentalPublicationGateway также вызывает локальное сжатие изображений.

Изменение поля запускает applicability после 500 мс тишины. После первой ручной проверки её результат обновляется с задержкой 1200 мс. Результаты не применяются к уже изменённому или уничтоженному экземпляру формы. Счётчик editVersion служит для отсечения поздних ответов и различения запусков расширения.

## API

Все маршруты ниже находятся под /api/workspace/rental и требуют сессию и доступ к кабинету.

- GET editor — публичная схема интерфейса.
- POST address/suggest и address/select — адресный поиск и выбор.
- POST analyze — извлечение проверяемых предложений из текста через ИИ.
- POST normalize — нормализация текущей формы по актуальной схеме.
- POST applicability — применимость полей по площадкам.
- POST prepare — подготовленные значения и замечания для проверки.
- POST extension-config — {id, revision, card}; компиляция инструкций из текущих данных.

id — случайный идентификатор экземпляра формы; revision — локальный номер его изменений, а не версия записи базы. Входные данные, версия схемы и площадки проверяются сервером. Селекторы и действия берутся только из доверенных reference-файлов; переданные клиентом инструкции не исполняются.

## Передача на площадки

1. Пользователь нажимает «Опубликовать». Angular передаёт RENTAL_RUN, текущую форму, локальный номер изменений и фото.
2. bridge.js проверяет origin и пользовательский клик, затем один раз вызывает extension-config. Ошибки подготовки возвращаются пользователю.
3. Сервер возвращает значения и runtime/browser-инструкции для выбранных площадок.
4. Service worker расширения проверяет контракт, связывает задания с origin, кабинетом, экземпляром формы и вкладками. Повторный запуск той же версии не создаёт дубликаты.
5. Скрипты площадок получают задание только в назначенном документе. Фоновая вкладка ждёт активации, форма — появления элементов. Фотографии ждут разблокировки загрузки.
6. REPORT передаёт прогресс расширению; Angular опрашивает RENTAL_STATUS каждые 2,5 секунды.

Расширение 0.9.11 сообщает rental-publishing, rental-address-suggestions и rental-form-session. Последний признак предотвращает запуск с прежним протоколом.

Фотографии до запуска находятся в памяти страницы. Во время выполнения расширение использует свой IndexedDB для фото и storage.session для заданий. Срок задания — 2 часа. Обновление страницы площадки и возврат через историю не дают нового разрешения на заполнение. Ручная пауза сохраняется. Переходы после заполнения, подтверждение подачи и продвижение выполняет пользователь.

Для улицы карточка хранит двухбуквенный тип («ул», «пр», «пе» и т. д.). Kufar, Realt и Domovita выбирают первую доступную подсказку нужного типа, а если такой нет или тип не указан — первую доступную. Onliner получает населённый пункт: единственный вариант либо полное совпадение без учёта регистра. Realt и Domovita используют свои зависимости адресных полей. Отчёт заполнения не означает подтверждённую публикацию.

## Справочники и проверки

Рабочий комплект: data/rental/apartments_long_term_rent. manifest задаёт схемы, планы подготовки, привязки и browser-рецепты. ReferenceValidator проверяет комплект, версии и контрольные суммы. Обновление комплекта меняет schemaVersion.

ArchUnit проверяет направление зависимостей Java. TypeScript-проверки запрещают компоненты с прямым транспортом и правилами площадок. Тесты проверяют подготовку, ИИ, адреса, изоляцию сессий, неактивные кнопки интерфейса, отсутствие записи данных формы, передачу текущих значений, работу фоновых вкладок и ручное подтверждение публикации.
