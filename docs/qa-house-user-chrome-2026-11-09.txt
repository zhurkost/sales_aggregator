Подтверждённые причины и исправления 0.9.28
1. Добавление локального фото во время ИИ меняло общую ревизию и молча отбрасывало ответ.
   Для ИИ используется ревизия содержимого; фото продолжают инвалидировать проверку
   готовности. Ручное изменение полей отменяет старый ответ с понятным сообщением.
2. ИИ предлагал contact.name="Собственник" с одноимённой цитатой.
   Общий промпт разделяет роль и имя, сервер отбрасывает названия ролей в поле имени.
3. Пропускались заголовок, плита и положительное разрешение на питомцев.
   Промпт требует сверять уникальные поля площадок. Для пропущенного/отбракованного
   заголовка и краткого описания разрешена одна дополнительная попытка только этих
   полей. Она не может заменить проверенные факты. При неудаче данные сохраняются,
   для отсутствующего заголовка выводится сообщение о ручном заполнении.
4. Onliner: сначала ищется полное совпадение исходной подписи без учёта регистра;
   удаление приставки сельсовета используется только если такого совпадения нет.
   Неоднозначные одинаковые подписи по-прежнему остаются для ручного выбора.
5. Постоянное предупреждение о сопоставлении адреса оставалось даже после успешного
   выбора. Для адреса с активным контролом статус определяется результатом этого
   контрола, а не статическим предупреждением подготовки.
6. Фото Kufar: подтверждено ограничение клиента, а не потеря данных при передаче.
   Файлы 5838/6049 байт отклонялись, 15873 и 138530 байт принимались.
   При одинаковом разрешении 640×480 файл 6049 байт не принят, 138530 принят.
   Код https://content.kufar.by/static/app-fe-services/_next/static/chunks/1q-ey-4ydog5d.js:
   size<=10240 -> ошибка; size>10485760 -> ошибка;
   при size<=102400 дополнительно проверяются width>=200 и height>=200.
   В схеме домов уточнены байтовые лимиты; browser-контрол содержит minFileSizeBytes=10241.
   Расширение объясняет отказ до CLAIM_PHOTOS и не делает повторные загрузки/дубликаты.
   Увеличение веса файла искусственным заполнением не применяется.

Проверка исправлений
Node: 120 тестов; Angular/Vitest: 55; Java: 147. Финальные сборки фронта и бэка успешны;
комплект схем/маппингов трёх категорий прошёл проверку целостности.
Регрессии: локальные фото во время ИИ, ручное изменение во время ИИ, имя/роль,
одна попытка восстановить заголовок, сохранение фактов при отказе ИИ, точное совпадение
Гродно перед одноимённой деревней, граница фото 10240/10241, адресные предупреждения.
Настоящий ИИ проверен на изолированной копии сервера для Гродно BYN, Бреста USD и

Колодищи EUR — проверка ИИ и подготовки, не третий сквозной запуск четырёх живых форм.
После этой проверки дополнительно уточнена инструкция не путать явно названный залог
за два месяца с предоплатой и не задавать лишний вопрос о таком залоге.

Ограничения проверки
Живой первоначальный сквозной прогон выполнен с установленным 0.9.27.
Исправленный алгоритм autocomplete дополнительно выполнен диагностическим драйвером
на настоящей открытой форме Onliner. Он выбрал исходную подпись «Гродно» среди пяти
вариантов и подтвердил done=onliner.address_query. Knockout-модель: address/user_address
«Гродно», latitude=53.6834599, longitude=23.8342648. Старые координаты заменены.
Это проверка производственного алгоритма через драйвер, а не переустановка расширения.
Исправленный 0.9.28 проверен автоматическими регрессиями; результаты старого расширения
не выдаются за повторный живой прогон новой версии. Для применения нужен reload/update
расширения в Chrome и новый запуск из обновлённого кабинета.
