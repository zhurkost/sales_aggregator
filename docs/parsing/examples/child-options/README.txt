УЧЕБНЫЙ ПРИМЕР CHILDOPTIONS · КОНТРАКТ 2.2

Все названия и коды вымышлены. Файлы не подключены к приложению, это не скрапинг
площадки и не завершённый этап B: одной площадки недостаточно для его приёмки.
Нормативное описание: docs/parsing/child-options-contract.txt.

common.json — общий справочник. platform.json — условный справочник площадки.
mapping.json — прямые связи трёх полей и шести choice (всех уровней).
binding.json — три записи needs_review без выдуманных селекторов.

options у item.class содержит корневые варианты. Каждый выбор ведёт по
childOptions к следующему уровню. Поля item.subclass и item.variant объявлены
отдельно, но их options пусты: варианты находятся в дереве, level указывает
на поле. parent_option_id связывает поля уровней, не заменяет родителя choice.

Пример карточки (схема будущей интеграции):
{"values":{"item.class":"item.variant.a.standard"}}

Общий путь: item.class.a → item.subclass.a → item.variant.a.standard.
Прямые связи дают site.class.a → site.subclass.a → site.variant.a.standard.
После проверки дополнительных условий подготовленные поля площадки:
{"site.class":"A","site.subclass":"A1","site.variant":"01"}
Не путать id узла и value сайта. Код "01" остаётся строкой с ведущим нулём.

Проверочные случаи:
1. item.class.a → только site.class="A"; неизвестные уровни не заполняются.
2. item.subclass.a → site.class="A", site.subclass="A1"; исполнения нет.
3. item.variant.a.standard → A/A1/01.
4. item.variant.b.standard → B/B1/01. Одинаковые name="Стандарт" и value="01"
   не делают варианты разных родителей одним узлом.
5. После смены выбора на item.class.b бывший выбор исполнения А не сохраняется.
6. Неизвестный id → needs_review, а не поиск по подписи/первый вариант.
7. Если в копии mapping убрать связь item.subclass.a, но оставить связь её
   потомка, проверка должна отклонить такой mapping. Восстанавливать пропущенную
   связь по конечному узлу нельзя. Если убрать обе связи зависимой ветви,
   остаётся допустимый частичный mapping: только A и needs_review для остального.
8. Если в копии mapping направить исполнение А к site.variant.b.standard,
   проверка целевых родителей должна отклонить связь.
9. childOptions: [] с options_complete:false (в отдельной проверочной копии)
   означает недоисследованную ветвь. Не считать её подтверждённым концом.

Проверки файлов не равны проверкам Angular, Spring или расширения. Исполнитель
node_lookup и динамическая отрисовка деревьев требуют отдельной реализации.
