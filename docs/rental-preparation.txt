АРЕНДА КВАРТИР: ПОДГОТОВКА ЗНАЧЕНИЙ И DADATA
Версия runtime: 1.0. Дата: 2026-11-01.

Что работает
В кабинете работает форма «Аренда квартир». Angular получает схему с сервера,
показывает поля, позволяет выбрать адрес DaData и проверить подготовку.
Форма и фотографии существуют только в памяти открытой страницы.

Сервер преобразует decimal/integer без округления, нормализует телефон как
строку, экранирует текст для HTML-редакторов и атомарно собирает multi_enum.
Ноль, false и отсутствие значения различаются. Условия групп распространяются
на их дочерние поля в runtime, не изменяя исходные файлы исследователей.
Редактор показывает зависимые поля и варианты только после выбора их условий.
Изменение улицы делает прежний вариант дома непригодным для подготовки.
Цена зависит от успешного выбора валюты. Конвертация валют не выполняется.
Этаж выше этажности и недопустимая точность вызывают уточнение.

Адрес
Ключ DADATA_API_KEY доступен только серверной стороне. По умолчанию Spring
обращается к фиксированному HTTPS endpoint DaData. В режиме Cloudflare relay
ключ хранится в Worker Secret, а Spring использует DADATA_RELAY_URL и отдельный
DADATA_RELAY_TOKEN. Worker принимает запросы только с IP VPS и с этим токеном.
В обоих режимах нет redirects и передачи профиля/контактов. Поиск
ограничен Беларусью; результат дополнительно фильтруется по country_iso_code=BY.
Выбор человека обязателен. Уточнение count=1 вызывается для unrestricted_value
ранее предложенной подсказки; смена ID/страны отклоняется. Подсказки, их ID и
кэш разделены по кабинету, имеют TTL и ограниченный размер. Timeout, 429/5xx,
лимит запросов, отсутствие ключа/результатов дают понятное сообщение. Автоповторов
со скрытым расходованием квоты нет. Ключ и адресные запросы не логируются.

Для Беларуси fias_id может быть OSM way/node, а fias_level=-1 при найденном доме.
Сохраняются фактические составные части, координаты и точность qc_geo. Точку дома
переносим только при точности 0 и совпадении обеих осей с подтверждённым адресом.
Правка адреса сбрасывает прежнее подтверждение/координаты. Корпус сохраняется
отдельно; буквы и дроби номера дома не отбрасываются.
Источник документации: https://dadata.ru/api/suggest/address/ (проверено 2026-11-01).
Живой smoke-test: публичный адрес дома в Минске, получение и выбор подсказки.

Ограничение: ID DaData НЕ являются ID Kufar/Realt/Domovita/Onliner. Неподтверждённые
native address-objects и неоднозначные выборы не генерируются из одного названия.
Runtime возвращает подготовленные части и явные issues для подтверждения на
площадке. Автозаполнение каждой внешней формы и публикация этим изменением
не заявляются. publicationReady всегда false; dataReady относится только к
известным правилам подготовки. Files не сжимаются/обрезаются/скачиваются; их
принятие и неизвестные ограничения требуют проверки площадки.

Хранение и запуск
Рабочие справочники и runtime-планы находятся в data/rental/apartments_long_term_rent
в GitHub и включаются в архив релиза вне Angular-статики.
Задать переменные окружения Spring (локально — игнорируемый .dev.vars):
  DADATA_API_KEY=<ключ подсказок>
  RENTAL_REFERENCE_DIR=<путь к data/rental/apartments_long_term_rent>
При npm run dev путь подключается автоматически. При развёртывании используется
/opt/autopost/current/data/rental/apartments_long_term_rent.
При проблемах прямого доступа VPS к DaData вместо DADATA_API_KEY задать:
  DADATA_RELAY_URL=https://<worker>.workers.dev/suggest
  DADATA_RELAY_TOKEN=<случайный серверный токен, минимум 32 символа>
Инструкция: ops/cloudflare-dadata-relay/README.md. Ключ провайдера в этом режиме
хранится в Cloudflare; frontend и расширение менять не требуется.
Комплект содержит manifest.json, integration/*_common.json,
четыре каталога <platform> с исходными схемами и runtime/preparation_<platform>.json.
Источник рабочих файлов — каталог data/rental/apartments_long_term_rent в checkout.
Планы используют SHA-256 компактного JSON common и соответствующей схемы.
При рассинхронизации сервер блокирует подготовку с 409, а не применяет старые коды.
Версия карточки охватывает common и все runtime-планы с хешами исходных схем:
смена кодов отдельной площадки тоже требует повторной проверки старой карточки.
Репозиторий содержит рабочие справочники и отдельные синтетические тестовые данные.

API внутри кабинета, с обычной сессией/Origin и X-Autopost-Workspace:
  GET  /api/workspace/rental/editor — модель редактора, доступность подсказок;
  POST /api/workspace/rental/address/suggest — {query};
  POST /api/workspace/rental/address/select — {id} из подсказки этого кабинета;
  POST /api/workspace/rental/extension-config — {id,revision,card}, текущие данные формы;
  POST /api/workspace/rental/prepare — {schemaVersion,values,extras,platforms,address}.
values — словарь common Option.id → строка либо files-массив.
extras — словарь platform → source Option.id → типизированный код/значение;
числовые строки уточнений разбираются на сервере через BigDecimal.
Ошибки не включают тела ответов провайдера, ключ или данные чужого профиля.

Runtime-план (отдельный от статического parsing_format_rule v1.2)
runtime_version="1.0", category_id, platform, schema_hash, common_hash,
constants — подтверждённые значения маршрута; fields — по одной записи на target.
Базовые identity/lookup/files сохраняют значение/точный код/порядок вложений.
Новые conversion.kind:
  decimal: target="number"|"integer", requires=[native IDs], currency_field,
           integer_currencies (если формат валюты площадки не допускает дробь).
  phone: format="E164"|"BY_NATIONAL"; без to_number, обрезания/угадывания страны.
  plain_text_html: экранирование &, <, >, кавычек; переносы в <br>, один <p>.
  multi_lookup: members=[{common_option_id,values:[{from,to}]}]. Один агрегатор
                объединяет подтверждённые варианты с явными extras. Неизвестное
                не становится отрицанием, неподдерживаемое даёт needs_review.
addresses=[{platform_option_id,part,scalar_verified}]: точное уникальное совпадение
подписи допускается только после явного подтверждения полноценности scalar native.
По текущим адресным схемам scalar_verified=false: это не готовые geocoder adapters.
coordinates=[{platform_option_id,axis:"latitude"|"longitude"|"pair"}].
checks=[{left,right,message}]: проверка left <= right без изменения данных.
review=[{field,message}]: не покрытая исполнительная проверка при наличии поля;
field="" означает ограничение всей ветви.
Коды/специфика площадок живут в версионируемых планах из Git. Не загружать планы от пользователя
и не превращать этот внутренний endpoint редактора в публичный API справочников.

Regex
Проверяется ограниченный переносимый ASCII-поднабор исходных patterns. Наблюдённая
группа [\w-\.] явно экранируется как [\w.\-]; lookaround, backreference и Unicode
properties не исполняются как якобы равнозначные JavaScript. Неподдерживаемое
правило требует проверки на площадке. Разные ограничения email не становятся
глобальными для common.

Проверки
npm run test:backend — преобразования, условия, списки, typed false/0, precision,
адресная изоляция и кэш, регистрация/кабинеты, ревизии карточек.
npm run test:frontend — сохранение правок при конкурентных ответах, отсутствие
автовыбора первой подсказки, сброс адресного подтверждения, сохранение дробного текста.
npm run build:frontend — Angular production build.
Поведенческие проверки используют вымышленные коды и тестовые контакты.
Отдельный контрактный тест проверяет рабочий комплект справочников из Git.

Развёртывание
Рабочая ветка — master. Коммит/PR не обновляет действующий VPS.
Архив релиза содержит рабочий комплект из Git; перенос отдельного снимка не нужен.
API-ключи остаются в серверном окружении и не добавляются в Angular environment.
Исторические данные SQLite при развёртывании не затрагиваются.
