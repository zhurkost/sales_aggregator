3. Фактически исследованные ветви

  daily/Сдаче посуточно. Исследована только rent.
- F2: пять типов: flats/Квартиры, room/Комнаты, cottages/Коттеджи/Дома,
  garage/Гаражи, commercial/Коммерческая. Исследована только flats.
- F3: полный доступный начальный шаг: Адрес, Контакты, О квартире,
  Фотографии, Описание, Цена и условия сделки и кнопка «Далее».
- Комнаты: все строковые коды 1,2,3,4,5,6,7 реально выбраны; checked
  подтверждён после каждого выбора. Набор контролов и секций не изменился.
  Студия как отдельный объект/переключатель/вариант комнат не обнаружена.
  Это не доказывает отсутствие поддержки студий за доступным шагом.
- Адрес: Минск выбран, пройдена цепочка улица → дом; карта отобразила
  выбранный адрес. Затем выбраны Брест и д. Копище Минского района.
  При смене населённого пункта улица/дом очищались, улица активна,
  дом заблокирован до выбора улицы. Независимые вводы района и метро
  в этих состояниях не появились. Полный адрес в результатах не сохранён.
  Для Бреста и Копища выбор конкретной улицы/дома не выполнялся:
  охват этих двух ветвей ограничен уровнем населённого пункта.
- Удобства: все пять включены и выключены отдельно; новых полей не возникло.
  Пустой набор после взаимодействия вызвал локальную ошибку обязательности;
  выбор одного убирал ошибку, возврат к пустому снова вызывал её.
- Валюта: USD, EUR, BYN, RUB реально выбраны; состав формы не изменился.
  Период платы фиксирован подписью «в месяц», переключатель периода не найден.
- Комиссия: Есть комиссия → Нет комиссии → снятие ответа; проверено взаимное
  исключение и три состояния. Поле суммы/процента комиссии не появилось.
- Планируемая продажа: Да → Нет → снятие ответа; проверены три состояния.
- Кому сдаётся: student, animals, children включены и выключены отдельно;
  дополнительных полей не возникло. Независимых полей курения и даты въезда
  на доступном шаге не обнаружено.
- Телефоны: первичный ввод, затем два нажатия «Добавить другой номер».
  Подтверждены поля phones.0, phones.1, phones.2.contact_phone.

Полный конечный охват: комнаты (7), удобства (5), кому сдаётся (3).
Для сделки и типа в схеме оставлены только подтверждённые коды целевой

Стабильный API-источник и полный каталог их нативных кодов не установлен.
town_id — скрытое поле; внутренний street_id замечен в автоматически
сформированной ссылке оценки, хотя отправляемый DOM содержит street_name.
Коды адресов и структура выбранного объекта требуют отдельной реализации.

улиц/домов, проверка пагинации и всех совпадений не выполнялись.

town → street → house; точные координаты/автозаполненные внутренние значения

Структурированный адрес, асинхронная подсказка и произвольная повторяемость
телефонов не имеют полноценного представления/исполнителя в этом контракте.
Три пустых адресных enum и один пустой currency enum — явные стоп-факторы
для исполнения и рабочих lookup-маппингов, не законченные справочники.

6. Привязки и фактическая проверка
Сохранено 11 простых set_value-привязок по уникальному input[name=...].
Для каждого селектора непосредственно в форме подтверждены ровно одно
совпадение, visible=true, enabled=true; выполнены штатный fill пустой строкой
и переход фокуса Tab без отправки. Непустое объявление не вводилось.
Проверка verify.value_equals описывает требуемую проверку результата будущего
заполнения, а не доказанную серверную приёмку. Содержательные значения,
маска телефона, нормализация чисел и серверная валидация не проверены.
timeout_ms=10000 — выбранный операционный бюджет ожидания привязки,
а не ограничение площадки. Дополнительные телефонные bindings применимы
только после создания соответствующих пустых строк интерфейсом; сама
последовательность добавления в исполняемом JSON не описана.
Путь/состояние формы должен быть F3; перенос на поздние шаги не проверялся.

Не созданы привязки:
- для enum и multi_enum: нет утверждённого формата параметров выбора
  варианта/набора по данным; массив селекторов не выдан за выбор первого;
- для комиссии/планируемой продажи: парные checkbox с пустым value и
  повторяющимися id, неизвестна нативная сериализация и трёхзначная стратегия;
- для адреса/карты: требуется асинхронная последовательность, проверка ID
  выбранного объекта и зависимых очисток, текущий контракт её не задаёт;
- для rich-text: требуется формат представления и проверка editor-content;
- для YouTube: модель files должна быть адаптирована к одному текстовому
  контролу youtube_link; прямое помещение массива в input недопустимо;
- для фото: отсутствует проверка files_accepted; видимость input и его accept
  не являются подтверждением приёма, авторизация/телефон не подтверждены.
Сгенерированные React id вида field-:rd: повторяются внутри групп и не
использованы как уникальные binding-селекторы; react-select id сессии не
объявлены стабильными привязками для исполнения.

7. Наблюдения, выводы, неизвестное и кандидаты
Наблюдения: наличие контролов, их DOM-типы/имена/строковые коды, видимые
тексты, checked-состояния, очистка зависимостей адреса, полный список валют
в UI и локальная ошибка пустых удобств подтверждены на F3.
Выводы модели отдельно от транспортного формата: boolean у has_commission
и sale_planned передаёт смысл явных ответов да/нет. API-коды и нативные
имена этих пар не установлены; отсутствие ответа должно оставаться null.
Никакой unchecked набор не назначен значением по умолчанию false.
У images/video тип files задаёт ссылки на исходные вложения согласно
контракту; бинарные данные, чужие фото и upload-токены отсутствуют.

Неизвестны required/границы большинства полей, числовые форматы и API-типы,
пределы телефонов, связь этажей/площадей, все региональные особенности.
Адресные значения службы, карта и координаты не подготовлены к исполнению.
По фото известны роль, chooser multiple, accept и сортировка, но реальный
серверный список MIME/расширений, количество, размер отдельного/суммарного
файла, разрешение, соотношение сторон, обложка и признаки принятия неизвестны.
accept=image/*,.jpg,.jpeg,.png сохранён как наблюдение, не как доказанное
серверное ограничение: широкое image/* и перечисление расширений не сведены
к вымышленному ограничению только JPEG/PNG. Никакой files.validation из этого
не выдуман. Допустимость внешних URL фотографий не установлена.
Для видео неизвестны проверка URL, поддержка иных хостингов, файловая
загрузка, длительность и размеры. Отдельная планировка/документы не найдены.
Не проверены авторизованный, агентский и последующие шаги.

Кандидаты для последующего заполнения/интеграции, не рабочие маппинги:
- актуальные коды валют и динамические справочники адреса;
- семантические числа для шести text-контролов (3 площади, 2 этажа, цена)
  с доказанными форматами и явными преобразованиями, если их требует площадка;
- асинхронное разрешение адреса/ID, корректное обращение с координатами;
- повторяемые контакты, подтверждение телефона штатным владельцем;
- трехзначные условия комиссии/продажи, rich text, YouTube files→URL;
- загрузка фото и проверка принятия без выдуманной обработки файлов.
Соответствия другим площадкам в этом задании не исследованы. Общие поля,
подтверждения двумя площадками и common/mapping-файлы не создавались:
они принадлежат отдельному интегратору.
